## 3. Findings

- **Detection signal cross-check (per Lote 10.6bis P0-W7-4 magnitude
  pinning):** the runbook's 5-min detection target requires the
  SLO-FRESH-GC sustained metric (DASH-GC panel 10) — NOT the
  sweeper-tick-stale alert which fires only after `> 1h`. The audit
  documents this explicitly so on-call engineers know to look at the
  faster signal.
- **Reconcile orphan-R2 detection arm:** WI-S06-005 ships the
  `OrphanR2Detected` decision arm; refcount is NEVER mutated when
  `r2_present=false AND deleted_at_ms.is_none()` — would amplify the
  inconsistency. Audit emit deferred to S-09 reclaim task per the WI
  §1.4 cross-reference to WI-S06-004 R2→D1 ordering.
- **Physical-delete strict-`>` post-grace boundary:** WI-S06-004
  ships the off-by-one anti-pattern pinning via `CountingPhysicalDeleteClock`
  auto-advance fixture; loosening from `>` to `>=` is a data-loss bug
  (deletes a blob exactly at the grace boundary which the runbook's
  undelete path would otherwise still recover).
- **Cron alarm re-arm idempotency:** WI-S06-001 scheduler property
  tests assert the alarm re-arm path is structurally idempotent; the
  jitter helper produces region-deterministic offsets so `sam` and
  `iad` cron ticks don't thunder-herd against each other.
- **Tombstone race fix path:** the runbook's hot-fix (write path lê
  tombstone_log + soft-block 24h re-write se digest tombstoned
  recente) + cold-fix (tombstone como hard-block durante grace
  period; 410 Gone if < grace) align with the WI-S07 forward
  INV-DEDUP-CONSISTENCY foundation.
