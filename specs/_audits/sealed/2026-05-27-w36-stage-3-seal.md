### §2.1 Notes on edge cases

- **`corelink-server` (container) holds a dangling `corelink-stripe-real`
  dep.** Its `src/*` only references `corelink_stripe_real::*` in
  doc-comments (`//!` / `///`), but the `[dependencies]` entry in
  `crates/corelink-container/Cargo.toml` is retained. cargo-deny operates
  on the cargo dep-graph (Cargo.toml-level), so the crate IS a direct
  parent and MUST be in the wrappers allowlist. A separate
  cleanup audit may remove the dangling dep later; we do NOT scope-creep
  into that here.
- **`corelink-billing-stripe-materializer`** — Trigger A moved src
  imports to `corelink-billing-stripe-traits`. The `corelink-stripe-real`
  dep is retained because `tests/materializers_e2e.rs` still constructs
  concrete `WebhookDispatcher`, `FixedClock`, `RecordingSliRecorder`,
  and `compute_signature` from `corelink_stripe_real::*`. Cargo treats
  test dependencies declared in `[dependencies]` as production graph
  edges, so the wrapper entry is required.
- **`corelink-dsr-statuspage-scheduler` — `corelink-statuspage-real`
  edge** is a Trigger B cfg-gated fallback. Native target consumes
  `corelink-ops::statuspage`; wasm32 falls back to direct import because
  `corelink-ops` pulls `tokio` → `mio` (mio is wasm32-incompatible).
- **`corelink-clerk-cf` — `corelink-statuspage-real` edge** is the
  wasm32-only CF Worker cron entry point
  (`src/dsr_statuspage_cron.rs`) consuming `bridge_to_report`,
  `StatuspageWasm32Client`, and `InMemoryStatuspageAuditSink`. Per the
  Trigger B architectural note (scheduler is native-only; wasm32 cron
  lives in clerk-cf), this is the canonical wasm32 entry point.

## §3. Lockdown rule set

### §3.1 Mechanism

cargo-deny v0.19.4 `[bans] deny` with `wrappers = [...]` allowlist.
Semantics: the named crate is banned as a direct dependency UNLESS the
direct parent appears in `wrappers`. Transitive deps through allowed
wrappers remain legal — this is exactly the "umbrella-only" topology
we want.

### §3.2 deny.toml diff

```toml
# crates/.../deny.toml (workspace root)
[bans]
# (existing rules retained: multiple-versions, wildcards, skip, etc.)
deny = [
    # (existing org-wide bans)
    { crate = "openssl",     reason = "use rustls (WASM-friendly + no system OpenSSL link)" },
    { crate = "openssl-sys", reason = "transitive ban; rustls only" },
    # Wave-36 Stage 3 — adapter HTTPS crates lockdown
    { crate = "corelink-stripe-real", wrappers = [
        "corelink-adapters-cloud",
        "corelink-billing",
        "corelink-billing-stripe-materializer",
        "corelink-server",
        "e2e-signup-flow",
    ], reason = "Wave-36 Stage 3 lockdown: use corelink-billing::stripe or corelink-adapters-cloud::stripe umbrella" },
    { crate = "corelink-statuspage-real", wrappers = [
        "corelink-adapters-cloud",
        "corelink-ops",
        "corelink-dsr-statuspage-scheduler",
        "corelink-clerk-cf",
    ], reason = "Wave-36 Stage 3 lockdown: use corelink-ops::statuspage or corelink-adapters-cloud::statuspage umbrella" },
    { crate = "corelink-slack-real", wrappers = [
        "corelink-adapters-cloud",
        "corelink-ops",
    ], reason = "Wave-36 Stage 3 lockdown: use corelink-ops::slack or corelink-adapters-cloud::slack umbrella" },
    { crate = "corelink-clerk-cf", wrappers = [
        "corelink-adapters-cloud",
        "corelink-auth",
    ], reason = "Wave-36 Stage 3 lockdown: use corelink-auth::clerk_cf or corelink-adapters-cloud::clerk umbrella" },
]
```

## §5. Charter compliance recap

- **No `--no-verify`.** Pre-commit hooks ran clean.
- **No new `#[allow]` lints.** cargo-deny is a supply-chain policy
  layer, not a Rust lint subsystem; nothing to allow at the source
  level.
- **No relaxation of existing rules.** `[advisories]`, `[licenses]`,
  `[sources]`, `[bans] multiple-versions`, `[bans] wildcards`,
  `[bans] skip` left untouched. Only the `[bans] deny` array was
  extended (additively, after the org-wide `openssl*` bans).
- **`INV-AUDIT` preserved.** deny.toml is a CI gate input; runtime
  audit chain unaffected.
- **`ADR-S12-045` extended.** The cargo-audit / cargo-deny /
  dependabot policy ADR receives a new lockdown clause via this
  audit's reference. (Cross-ref noted; ADR text not edited as that
  would scope-creep beyond this SEAL.)
- **Hard-pause triggers honored.** All four mandate triggers were
  evaluated; none activated (no real consumer leak; all affected
  builds GREEN; deny.toml parses).

## §7. Architectural impact

Post-W36:

- New consumer code that attempts a direct `corelink-stripe-real` (or
  one of the 3 siblings) dep declaration fails CI cargo-deny gate at
  the first PR with explanatory error pointing to the umbrella path.
- The "absorbed-but-canonical" crate pattern (Option-A from W33
  charter) is now provably stable: the wrappers list documents the
  five legal direct importers (4 umbrellas + 1 dangling legacy + 1
  workspace e2e), and the deny rule is the regression guard.
- Future absorbed-crate physical-split work (W33 follow-up §3 closure
  path (b)) becomes feasible incrementally: each wrapper can be peeled
  off independently by migrating its source to the canonical umbrella
  path, then dropping the wrapper entry.
