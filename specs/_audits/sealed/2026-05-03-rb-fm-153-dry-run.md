## 3. Findings

- **Independence canonical**: synthetic canary (CF Workers cron-trigger
  per region) is structurally independent of Grafana Cloud — canary
  loops continue from Enam + Weur + Apac when Mimir/Loki/Tempo
  endpoints are blocked. The canary observability health probe arm
  emits `corelink_canary_observability_health_failures_total{component=mimir|loki|tempo|dashboard}`
  as the SEV-3 alert source for Grafana Cloud outage detection;
  `prop_canary_assertion_ladder_canonical` 10k iter pins the decision
  arm boundary.
- **Twilio backup fail-OPEN canonical**: `corelink-slo` dispatcher
  fail-OPEN envelope (`evaluate_dispatcher_fail_open` variant) returns
  `AlertEvaluationOutcome::dispatcher_accepted=false` when PagerDuty
  primary path rejects; production wiring increments
  `corelink_alerts_dispatched_total{dispatch="fail"}` SEV-2 + retries
  via Twilio fallback. `prop_audit_emit_per_decision_arm` 10k iter
  pins the audit-row commits BEFORE the dispatch attempt so the alert
  is recoverable at the dispatcher boundary.
- **Cardinality budget local-first defense**: even when Mimir tenant
  ingest 5xx rejects, the runtime `corelink-analytics::CardinalityValidator`
  primary defense holds (per-instance `Arc<Mutex<>>` ledger + 20k
  per-metric / 100k global cap); Mimir tier limit is the secondary
  defense per sprint contract §15 R-Cardinality-explosion. The
  defense-in-depth pattern means cost protection is not contingent on
  Grafana Cloud availability.
- **Tracing exporter fail-OPEN canonical**: `corelink-tracing` ships a
  trait-abstracted `OtlpExporter` with a `record_exporter_failure`
  arm that lifts to the production-side fail-OPEN exporter-failure
  ledger `corelink_tracing_export_failures_total` SEV-3 alert source.
  Spans NOT lost during exporter outage; tail-sampling fail-OPEN to
  drop arm rather than panic.
- **3-region canonical** (Enam + Weur + Apac per `data_model.md §2.1`
  R2 region hints): `prop_three_region_decision_isolation` 10k iter
  pins per-region ledger isolation; Lote 10.9bis P1 R4 P1-10 corrected
  from IATA colocodes (IAD/LHR/BOM são CF colo codes for
  `request.cf.colo`, NOT R2 region hints).
