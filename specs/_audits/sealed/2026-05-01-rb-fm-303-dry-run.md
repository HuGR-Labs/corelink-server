# RB-FM-303 host-side dry-run — AC Cross-Tenant Breach

> **Sprint:** S-04 (Action Cache + Merkle + HKDF signing) · **WI:** WI-S04-006 §6.1.4
> **Runbook:** `specs/05_quality/runbooks/RB-FM-303-ac-cross-tenant.md`
> **Harness:** `scripts/rb_fm_303_dry_run.sh`
> **Date:** 2026-05-01 · **Mode:** host-side simulation (staging dry-run deferred until staging account provisioned)

## 1. Scope

Host-side dry-run validates the runbook step ordering + the
load-bearing cross-component invariants the on-call engineer would
exercise during a real AC cross-tenant breach (FM-303 catastrophic).
Does NOT page real PagerDuty / hit real Cloudflare R2-D1-KV / drive a
chaos PR introducing a tenant_id confusion bug into a real Worker —
those land in the staging dry-run when the CF account is provisioned
(see §5 forward).

Steps validated (per RB-FM-303 + WI-S04-006 §6.1.4):

1. **Detection** — cross-component property test
   (`prop_ac_full::prop_ac_full_stack_tenant_isolation_100k`) asserts
   every cross-tenant GET probe surfaces 404 AND the cross-tenant
   audit emit lands as `GetMiss` (not `GetOk`). 1 000 iter at PR
   speed; 100 000 iter nightly per WI §10.s04.006.2.
2. **Communication** — SEV-0 page synthesis stub; payload shape
   matches `RB-FM-303 § Comunicação`.
3. **Mitigação imediata** — degrade_mode flag toggle + AC TTL cron
   disable + entry snapshot + tenant identification + contaminator
   quarantine — each step is a runbook checkpoint exercised against
   the in-memory fixture.
4. **Diagnóstico** — TTL tenant-scoped eviction property test
   (`prop_ac_full::prop_ac_full_stack_ttl_eviction_tenant_scoped`) at
   10 000 iter green — INV-AC-EVICT-TENANT-SCOPED holds at the cron
   seam.
5. **Resolução** — REAPI v2 conformance suite re-run (10 / 10
   conformance tests pass); blocks production rollout if any
   conformance regresses.
6. **Forensics + Notificação obrigatória** — audit log query +
   customer notification template drafts ready (WI §6.1.10
   customer-facing communication assets are landing alongside the
   ship gate).
7. **Post-mortem hooks** — TLA+ INV-TENANT-ISOLATION coverage
   confirmation + regression test growth surface + FF-HR-002
   promotion consideration.
8. **Drift detection** — runbook canonical headers all present
   (`Detecção`, `Comunicação`, `Mitigação imediata`, `Mitigação
   completa`, `Forensics`, `Notificação obrigatória`, `Post-mortem`,
   `References`).
