## 3. Findings

- **TLA+ ↔ Rust cross-validation:** the 100k race property test is the
  load-bearing cross-check that `gc_correctness.tla::InvGCReRefProtected`
  holds against the real Rust impl (WI-S06-002 mark + WI-S06-003
  sweep). At the boundary case `ac_offset_ms ∈ {-1, 0, +1}` sampled
  exhaustively per iter, the protect-if-`>=` predicate fires correctly
  for offset ≥ 0 (ac.created_at_ms ≥ mark_started_at_ms = re-ref
  during mark = PROTECT) and the sweep arm fires correctly for offset
  < 0 (= no re-ref = SWEEP).
- **Adversarial fixture inputs (per WI §1.7 + Lote 10.6bis P0-W6-1):**
  the property test exercises three adversarial scenarios that would
  trick a regressed `LIKE '%digest%'` impl: (a) envelope mutation
  where `action_digest` STRING references the target as substring;
  (b) short-digest substring (16-char prefix in unrelated
  `action_digest`); (c) schema-evolution where `action_digest`
  mentions target but `blob_refs` is empty. All three correctly route
  to the SWEEP arm (because `blob_refs` is the load-bearing reachable
  set, not `action_digest`).
- **Off-by-one anti-pattern pinned:** the `prop_inv_gc_004_protect_if_ge_strict_boundary`
  property test would fail loudly if anyone regressed the predicate
  to `>` instead of `>=` (the canonical TLA semantic is `protect-if-equal-or-newer`
  per Lote 10.6 cycle 4 fix; loosening to `>` would lose the equality
  case and is a data-loss bug).
- **Audit fail-closed envelope:** sweep emits
  `corelink.gc.sweep.protected_re_ref` BEFORE the candidate `status`
  flip; emit failure preserves the candidate row as `Candidate` and
  the blob_meta is NOT soft-deleted (production wiring rolls back the
  D1 batch).
- **Gap closure:** at the boundary case (offset = +1ms) the sweep
  arm correctly routes to PROTECT — the SRE on-call following
  RB-FM-404 would observe the `protected_re_ref` audit event and
  confirm the runbook hot-fix landed cleanly.
