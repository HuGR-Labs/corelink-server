# Weekly compliance digests — index & methodology

> **SOC 2 CC4.2 evidence** · auto-generated by `scripts/compliance-weekly-digest.py` every Monday 09:00 UTC via `.github/workflows/compliance-weekly.yml`. Closes **GAP-08** of `specs/_compliance/SOC2-EVIDENCE-ROLLUP-2026-05-15.md`.

## 1. Purpose

Each Monday at 09:00 UTC, the workflow runs the digest script, opens a PR with the resulting markdown file, and (if regression is detected) pages PagerDuty + posts a regression-comment on the PR. The Compliance Lead triages per `specs/_runbooks/RB-COMPLIANCE-WEEKLY-REVIEW.md`.

This README is:

1. The **canonical methodology** for the change-detection logic.
2. The **index** of every past digest under this directory.
3. The auditor-facing entry point for the CC4.2 evidence stream.

## 2. Methodology — what the digest tracks

| § | Domain | Source(s) | Detector |
|---|---|---|---|
| 1 | SOC 2 readiness | `SOC2-EVIDENCE-ROLLUP-*.md` §3.1 / §3.2 (newest by filename date) | week-over-week % delta for Implemented / Partial / Gap + Drata dashboard + internal scorecard + auto-collection rate |
| 2 | GAP register | `SOC2-GAP-ANALYSIS.md` summary table | set-diff vs previous digest's snapshot (§8); severity normalised to `{minor, major, blocking-ga}` |
| 3 | Vendor risk SLAs | `VENDOR-RISK-REGISTER.md` §2 register table | `days_since_last_review > cadence` (Critical 90d / Important 180d / Standard 365d) |
| 4 | Drill cadence flags | `BCP-DR-DRILL-CADENCE.md` DR-* entries + `specs/_audits/*-bcp-drill-*` evidence files | drill missed past grace window (Critical 0d / Important 7d / Standard 14d) |
| 5 | IR tabletop readiness | `IR-TABLETOP-SCHEDULE-2026.md` §2 default session slots + `specs/_compliance/ir-scenarios/TT-NN.md` | next-session date + T-7d brief window + facilitator artefact presence |
| 6 | Compliance CI gates | `.github/workflows/*.yml` filtered by tag substrings (`compliance`, `byok`, `cargo-deny`, `cargo-audit`, `cosign-sign`, `drata`, `lgpd`, `backup-daily`, `dr-drill`, `pentest`, `fips`, `license-audit`, `verify-fips`, `verify-lgpd`, `validate_specs`, `sbom`, `cold-restore`, `active-failover`) — queried via `gh run list` | conclusion in `{failure, timed_out, cancelled, startup_failure}` within last 7d |
| 7 | Regression verdict | derived from §§2–6 | exit code 1 + PD page + PR comment |
| 8 | GAP snapshot | parsed live from `SOC2-GAP-ANALYSIS.md` | next-week diff baseline (canonical state) |

### 2.1 Severity ordering for GAP register

`minor` < `major` < `blocking-ga`. The digest flags **only** upgrade transitions; downgrades are reported as informational (no PD page).

### 2.2 Vendor SLA tiers

| Category | Cadence letter | Cadence (days) | 1× breach action | 2× breach action |
|---|---|---|---|---|
| Critical | Q | 90 | email owner; review packet in 30d | PD page; ad-hoc review per RB-VENDOR-RISK-QUARTERLY-REVIEW.md §4 |
| Important | B | 180 | email owner; review packet in 30d | PD page; ad-hoc review |
| Standard | A | 365 | email owner; review at next quarterly | PD page; ad-hoc review |

### 2.3 Drill criticality

| Class | Drill IDs | Grace |
|---|---|---|
| Critical | DR-005..DR-010, DR-15, DR-16 | 0d |
| Important | DR-001..DR-004, DR-011..DR-014 | 7d |
| Standard | (post-GA additions) | 14d |

### 2.4 First-run guard

The very first digest cannot compute deltas (no reference). It is emitted with `regression: NO` and all `new`/`closed` lists empty by policy — this baseline becomes the diff anchor for week 2.

### 2.5 Source-of-truth invariants

- The **rollup** (`SOC2-EVIDENCE-ROLLUP-*.md`) is the source-of-truth for readiness %.
- The **GAP analysis** (`SOC2-GAP-ANALYSIS.md`) is the source-of-truth for GAP severity. Even if a GAP is described as "IMPLEMENTED" inline in the rollup, the digest treats the GAP-ANALYSIS frontmatter `doc_status` + the register-summary table as canonical. When the GAP-ANALYSIS doc is superseded, update `inherits_from` in this doc accordingly.
- The **vendor register** is the source-of-truth for review dates — Drata's vendor-module dashboard mirrors it but is not parsed.
- The **drill cadence** is the source-of-truth for drill IDs; evidence-file presence under `specs/_audits/` is the operating-effectiveness proof.

## 3. Escalation triggers (8)

The digest script exits 1 (which triggers PagerDuty + PR comment via the workflow) when any of these holds:

1. **GAP severity upgrade** detected (e.g. `minor → major`).
2. **Open GAP count rose** week-over-week (suppressed on first-run).
3. **Critical-class drill missed** past 0d grace.
4. **Important-class drill missed** past 7d grace.
5. **Standard-class drill missed** past 14d grace.
6. **Vendor 2× SLA breach** (any tier).
7. **Compliance-gate CI workflow** with conclusion `failure / timed_out / cancelled / startup_failure` in last 7d.
8. **Co-occurrence** of two or more of (1)..(7) — escalates severity one tier (handled by the runbook §4 matrix).

Triage details: `specs/_runbooks/RB-COMPLIANCE-WEEKLY-REVIEW.md` §4.

## 4. Operational use

- **Scheduled run:** Monday 09:00 UTC via `.github/workflows/compliance-weekly.yml` (cron `0 9 * * 1`).
- **Manual run:** `python3 scripts/compliance-weekly-digest.py --with-ci`
- **Preview only (no commit):** `python3 scripts/compliance-weekly-digest.py --dry-run`
- **Compare against a specific prior digest:** `--reference 2026-05-11`
- **Get JSON payload for tooling:** `--json`

## 5. Retention

- **Digest markdown files** are retained for the full SOC 2 Type II observation window (T+6m..T+18m post-GA = ≥ 12 months online, ≥ 7 years cold archive per `specs/03_architecture/compliance_matrix.md`).
- **GitHub Actions artefacts** are retained 365 days (set in the workflow).
- **Drata ingestion:** the `incident_response` EvidenceStream picks up merged digests on the next 03:00 UTC tick (per `SOC2-EVIDENCE-ROLLUP-2026-05-15.md` §4.1).

### 6.1 Evidence gap 2026-05-18 → 2026-08-10 (declared, not backfilled)

**No weekly digest exists for the thirteen Mondays between 2026-05-18 and
2026-08-10.** This is recorded here rather than quietly filled, because a
fabricated digest is worse than a declared gap.

**What happened.** The cron fired as scheduled; the digest script ran and
succeeded every time. Every run died in the tail that commits the file and
opens the PR:

| Date | Run | Failure |
|---|---|---|
| 2026-08-17 | 32016803572 | `gh pr create` → *"GitHub Actions is not permitted to create or approve pull requests"* |
| 2026-08-10 | 31378601701 | same lane |
| 2026-08-08 (`subprocessors-sync`, same class) | 31245724676 | job never started — `runner=""`, `steps=0`, 9s, `ubuntu-latest`: the hosted-Actions billing block |
| 2026-08-03 | 30813673838 | same lane |
| 2026-07-20 | 29739827151 | same lane |
| 2026-07-13 | 29248756088 | same lane |

Two distinct root causes, both since removed: the repository-level
*"Allow GitHub Actions to create and approve pull requests"* setting was off
(granted 2026-08-23), and the earlier lane ran on hosted runners under a
billing block (since migrated to `runs-on: corelink`). Two further defects
that would have kept the lane broken were fixed the same day (#1225): the bot
commit carried no DCO trailer, and a same-day re-run could not push.

**Why the gap is NOT backfilled.** `scripts/compliance-weekly-digest.py`
computes every metric from the repository's **current** state. Running it now
with a past date would emit today's numbers under that date — an artefact that
looks like contemporaneous evidence and is not. For CC4.2 the honest record is
this declaration: the control's *detective* function (the digest script and its
inputs) was continuously healthy and demonstrably re-runnable; its
*communication* function (PR + review) was interrupted for thirteen weeks by a
CI permission defect, and no compliance regression was detected on either side
of the gap (`2026-05-15` and `2026-08-17` are identical on every tracked
metric, which is itself evidence that nothing drifted unobserved).

**Auditor note.** The gap is bounded and attributable. Anyone verifying it can
re-run `python3 scripts/compliance-weekly-digest.py` against any historical
commit to reconstruct what a given week *would* have reported.
