## Root-cause diagnosis

### What we know (verified)
1. **Worker is alive and reachable.** A manual `POST /webhooks/clerk` with no svix headers returns `400 missing_svix_headers` — proves the worker is deployed and routed correctly.
2. **Clerk DOES deliver webhooks.** CF GraphQL `workersInvocationsAdaptive` shows invocation timestamps 2-4 seconds after each Clerk `users.POST` returned 200, with multiple retries per user (Svix backoff schedule).
3. **Every invocation completes with `subrequests = 0`.** The handler exits before any outbound `fetch(...)` — i.e. it never reaches `/_internal/pat/mint`, never reaches the Clerk PATCH `/v1/users/{userId}`, and never reaches any D1 write.
4. **Worker secrets are bound.** `wrangler secret list` confirms all 5 secrets are bound: `CLERK_SECRET_KEY`, `CLERK_WEBHOOK_SECRET`, `CORELINK_INTERNAL_AUTH_KEY`, `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`.
5. **D1 CONFIG_DB binding is correct.** `wrangler.toml` points at `d64742ea-e102-40b2-a844-ff02e3f94562` (corelink-prod-d1).
6. **No tenant row was ever inserted.** `SELECT tenant_id FROM tenant WHERE clerk_user_id = '<each user id>'` returned empty for all 3 test users.
7. **Clerk `public_metadata` was never written.** `GET /v1/users/{userId}` shows `public_metadata: {}` for the test user.

### Reading `apps/signup-worker/src/webhooks/clerk.ts`

The handler has only these early-exit branches (lines 287-341) BEFORE the first outbound fetch:
- `request.method !== "POST"` -> 405 (Clerk sends POST -> not this)
- missing `svix-id` / `svix-timestamp` / `svix-signature` -> 400 (Clerk includes all three -> not this)
- `verifySvixSignature(...)` returns `false` -> **401 `invalid_signature`** -> matches
- `JSON.parse(body)` fails -> 400 (Clerk sends valid JSON -> not this)
- `event.type !== "user.created"` -> 200 `ignored` (we're creating a user -> not this)
- D1 idempotency hit (existing tenant) -> would imply prior provisioning, but there is no row -> not this

By elimination, **every webhook is being rejected at `verifySvixSignature` with HTTP 401**.

### Root cause

**`CLERK_WEBHOOK_SECRET` bound on `corelink-signup-worker` does not match the signing secret of the registered Clerk webhook endpoint.**

This is the classic first-deploy svix bug: the endpoint was registered in Clerk and the signing secret was copied into a `wrangler secret put` call, but either:
- the wrong secret was pasted (a different endpoint's secret, or the publishable key, or a truncated value), OR
- the signing secret was rotated in Clerk after `wrangler secret put` was run, OR
- a trailing whitespace / `whsec_` prefix mismatch in the value passed to `wrangler secret put`.

`verifySvixSignature` at `apps/signup-worker/src/webhooks/clerk.ts:83-116` only returns `true` if at least one `v1,<base64>` candidate matches the locally-computed HMAC-SHA256 of `${svix-id}.${svix-timestamp}.${body}` keyed by the base64-decoded `CLERK_WEBHOOK_SECRET` (after stripping `whsec_`).

## Remediation (requires operator with Clerk dashboard access)

1. Open Clerk Dashboard -> Webhooks -> the endpoint pointing to `https://corelink-signup.humangr.com/webhooks/clerk`.
2. Click "Signing Secret" -> "Reveal" -> copy the `whsec_...` value verbatim.
3. From repo root:
   ```sh
   cd apps/signup-worker
   echo -n "whsec_<paste_here>" | node_modules/.bin/wrangler secret put CLERK_WEBHOOK_SECRET
   ```
   Confirm the secret update creates a new deployment (visible in `wrangler deployments list` as `Source: Secret Change`).
4. Re-run this E2E (create one Clerk user via Backend API, watch for the D1 `tenant` row within 10s).
5. If still failing, capture a live tail with `wrangler tail corelink-signup-worker --format=pretty` in the foreground while creating a user (background piping appears to drop events) and check for `invalid_signature` log output.

## Smoking-gun summary (one paragraph)

The signup pipeline is **wired correctly end-to-end** (worker deployed, D1 binding live, container internal auth key bound, route registered, Clerk delivering webhooks). The single failure is **secret-value drift between Clerk's webhook-endpoint signing secret and the `CLERK_WEBHOOK_SECRET` on `corelink-signup-worker`**. Evidence: 13 worker invocations across 3 test users, all completing with HTTP success but zero outbound subrequests — the only `verifySvixSignature`-passing return path requires an outbound fetch (`/_internal/pat/mint`), so the fact that no subrequest fires anywhere proves every webhook is being rejected at the signature check. Fix is a single `wrangler secret put CLERK_WEBHOOK_SECRET` once the dashboard secret is copied.
