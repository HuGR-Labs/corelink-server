CoreLink v1.0.0-GA — General Availability release

This signed tag freezes the first generally available CoreLink server release.
It is a release record, not a promise that designed or parked capabilities are
live. Statements below are deliberately limited to evidence bound to the exact
release identity.

================================================================
Scope and explicit non-claims
================================================================
- The five production Worker/container environments and the D1 migration
  ledger must match the deployment evidence named above at cut time.
- Designed, partially wired, dormant, parked, or unevidenced capabilities are
  not promoted by this tag. In particular this tag makes no GA-live claim for
  the four-provider BYOK lifecycle, Neon shadow synchronization, WebAuthn
  administration, customer R2 audit export, or its scheduled drain.
- Compliance documents and controls remain governed by their own status and
  evidence. This tag does not transform a draft, template, self-assessment, or
  planned external engagement into an attestation.
- Known carve-outs must be enumerated in the cutover attestation. No hidden
  debt is waived by applying this tag.

================================================================
Release gates
================================================================
- `framework-v1-0-0-ga` is a cryptographically verifiable signed tag, targets
  an ancestor of this release, and freezes `specs/00_framework.md` at v1.0.0.
- `scripts/validate_specs.py` and `scripts/validate_references.py` pass on the
  exact release commit.
- RB-GA-CUTOVER has a completed, content-addressed execution attestation for
  the exact release commit; a dress rehearsal is not execution evidence.
- Both release signers approved this exact source commit and evidence set.
- The release tag itself is created with `git tag -s` and verified locally
  before push; remote peeled-object readback must equal `__RELEASE_SHA__`.
