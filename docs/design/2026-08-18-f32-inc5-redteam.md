## VERDICT: SAFE-TO-FLIP

The OCI-flip surface (WP-E turns `OCI_PUBLIC_DEDUP_ENABLED=1` + un-comments the
alpine pin) is safe. **Cross-surface `_public` poisoning is structurally
impossible**, the writer set is exhaustively two verify-before-write paths, SSRF
is doubly-refuted, and OCI revocation is immediate + un-re-populatable.

**Blockers: 0.** One MEDIUM finding (F-1) and three low/accepted notes are
documented below. F-1 is a **pre-existing brew/pip edge condition that the OCI
flip does not touch** (OCI is never edge-served) — it is a recommended pre-flip
hardening, not a flip blocker.

### Pre-flip conditions (recommended, non-blocking)
1. **(F-1, MEDIUM)** Close the edge-revocation-window gap for
   revoke-by-`upstream_digest` before relying on fast public revoke during an
   incident. Exact fix in F-1. Does not gate the OCI flip.
2. **(GAP-E, process)** Confirm the WP-E manifest pin is the **compressed
   layer-blob** digest, not a `diff_id`, and that `GAP-E` (mirror populated
   `_public` for every active allowlist entry) is satisfied before the roll —
   otherwise dedup silently never fires (false-green).

### Top 3 findings
1. **F-1 MEDIUM** — edge `pubblock` KV marker is written only when the revoke
   body carries a bare `content_hash`; a revoke-by-`upstream_digest` (the
   documented incident path) never marks the edge, leaving a ≤60 s edge-serve
   window for **brew/pip** (`EDGE_PUBLIC_READ="serve"` is live). OCI unaffected.
2. **F-2 LOW** — the shared SSRF guard classifies IP **literals** only; a
   redirect/realm host that is a DNS name resolving to an internal IP is not
   caught (DNS-rebinding). Not reachable on the OCI flip (fixed upstream +
   verify gate), defense-in-depth only.
3. **F-3 LOW / accepted** — Open-Q4 bearer-TTL: an already-minted bearer reads
   `_public` for its full TTL after tenant suspend/erase. `_public` is public
   base-layer content, so this is a metering-lag, not a confidentiality break.

## Surface 1 — `_public` poisoning & the exhaustive writer set

**Invariant under test:** the `_public` *OCI-digest* writer set is exactly two
(tenant `finalize_upload`, admin mirror); every write verifies bytes against the
digest before the put; the flag/allowlist cannot be widened at runtime.

**Proof of safety.**

- **Writer #1 (tenant).** `OciMoatStore::finalize_upload` runs
  `OciDigest::parse(blob_key).verify_against_bytes(&session.buf)` at
  `crates/corelink-container/src/routes/oci.rs:568-572` **before** the
  namespace decision (`:589`) and the `moat.put` (`:594`). A digest-lie fails
  closed pre-write. The `_public` route fires only when
  `routes_to_public(blob_key)` = `self.dedup && self.allowlist.is_allowlisted`
  (`:286-288`, `:589-590`).
- **Writer #2 (admin mirror).** `fetch_verify_promote`
  (`crates/corelink-container/src/routes/public_mirror.rs:323-365`) gates on
  `is_allowlisted` (`:340`) → validates repository (`:345`) → SSRF-safe fetch
  (`:347`) → `verify_against_bytes` (`:353-355`) → `moat.put` (`:359`). Verify
  is unconditionally before put.
- **No third OCI-digest writer.** OCI `_public` keys are the **wire string**
  `sha256:<hex>` produced by `OciDigest::to_wire`
  (`crates/corelink-adapter-host/src/oci/digest.rs:122-123`,
  `format!("{}:{}", algo, hex)` — contains a colon). The only two writers of a
  colon-form `_public` key are the two above; both verify. `blob_exists`
  (`oci.rs:652`) delegates to `get_blob` (read-only). WP-G read-through is
  **deferred** (promotes per-tenant only by design; not present on main).
- **Runtime widening is impossible.** The flag is boot-read once
  (`crates/corelink-container/src/public_flags.rs:20-23`, exactly `"1"`) and
  injected as a plain `bool` into `OciMoatStore::new`
  (`oci.rs:810-812`); a live DO never re-reads env (activation = repin, per the
  module doc `:5-9`). The allowlist is `include_str!`-baked
  (`crates/corelink-container/src/public_base_allowlist.rs:27`) and degrades to
  deny-all on a malformed manifest (`public_mirror.rs:168`,
  `unwrap_or_default`). Neither can be widened by any request.

**Refutation attempt — the read path trusts the map.** `get_blob` returns
`_public` bytes **without** re-verifying them against `blob_key`
(`oci.rs:631-641`). So poisoning reduces to: *can any actor create the map row
`(_public, "sha256:<hex>") → attacker_content_hash`?* The map-INSERT SQL
(`adapter_cache.rs:113-135`) is reachable only through `MoatCache::put`, whose
`_public` callers are the two verify-gated OCI writers plus the bare-hex
package surfaces (Surface 4). A colon-form key can be produced by no other
writer, and the two OCI writers each proved bytes hash to that exact digest
before writing. **Poisoning the OCI read is structurally impossible** short of a
SHA-256 second-preimage. Not refuted → invariant holds.

## Surface 2 — the `repository` fetch locator (WP-A)

**Attack:** choose `repository` so the FIXED-upstream fetch returns
attacker-controlled bytes, or escapes the origin.

**Proof of safety.** `repository` is validated (`public_mirror.rs:373-403`):
non-empty, `[a-z0-9._/-]` only, no leading/trailing `/`, no empty component, no
`.`/`..` component. The blob URL is `Url::join`-ed onto the fixed origin and
then **re-asserted** to stay on the fixed scheme+host (`:517-523`) — a
scheme-bearing repo that host-swaps is rejected. Decisively: even a fully
attacker-chosen repo can only make the fetch **fail** or return the **genuine**
bytes for that digest, because the fetched bytes must pass
`verify_against_bytes` against an **allowlisted** digest (`:353-355`). Repo
choice cannot change which bytes are accepted. **Refutation attempt** (fetch a
different repo whose blob collides to the allowlisted digest) requires a SHA-256
collision. Holds.

## Surface 3 — SSRF: 307→CDN, token realm, rebinding

**Proof of safety for the flip.** The redirect policy stops any hop whose host
is an internal IP literal (`upstream_ssrf.rs:68-78`), covering loopback,
RFC-1918/4193, link-local incl. `169.254.169.254`, CGNAT, broadcast,
documentation, unspecified, and IPv4-mapped v6 (`:32-58`). The anon-token realm
is guarded by the **same** `host_is_internal_ip` classifier and forced to
`https` (`public_mirror.rs:475-482`). Upstream is pinned to
`registry-1.docker.io` (`:96`); the 307 `Location` and the `WWW-Authenticate`
realm are emitted by Docker Hub, not the caller — the caller cannot inject a
redirect target.

**Finding F-2 (LOW, defense-in-depth, pre-existing).**
`host_is_internal_ip` classifies **IP literals only** and explicitly does not
resolve DNS names (`upstream_ssrf.rs:20-23`, `:29-31`). A redirect/realm host
that is a *name* resolving to an internal IP (DNS-rebinding / split-horizon) is
followed. This is **not reachable on the OCI flip**: the only host in play is
Docker Hub's, and any SSRF success is still refuted by the mandatory
`verify_against_bytes` (internal/metadata bytes never hash to the allowlisted
digest) and by the admin-only, response-body-not-returned handler (no exfil
oracle — success is `{"status":"promoted"}`, `public_mirror.rs:252-260`). The
guard is shared with brew/pip/npm, so a rebinding hardening (resolve-then-check,
or an allowlist of upstream hosts) is a worthwhile follow-up but not a flip
blocker.

## Surface 4 — cross-surface `(namespace='_public', url_hash)` collision

`_public` is shared across OCI, brew, pip, and npm-metadata. The OCI read trusts
the map (Surface 1), so key-space partitioning is load-bearing.

**Enumerated `_public` writers and their url_hash space:**

| Surface | `_public` write | url_hash form | colon? | cite |
|---|---|---|---|---|
| OCI blob | yes | `sha256:<hex>` (wire) | **YES** | `oci.rs:590,594`; `digest.rs:122-123` |
| pip wheel | yes | `digest.to_hex()` bare hex | no | `pip.rs:118,135` |
| brew bottle | yes | `hex(blake3(path))` bare hex | no | `brew.rs:90-104`; `bottle.rs:83-91` |
| npm tarball | **no** (per-tenant) | n/a | — | `npm.rs:154,174` |
| npm metadata | yes, but separate KV store | `npm:meta:<pkg>` | yes (`npm:`) | `npm.rs:104` |
| bazel/turbo/sccache | no — only **reject** `_public` as a tenant sentinel | n/a | — | `bazel_v2.rs:1167,1180`; `auth_tenant.rs:41` |

**Proof of safety.** All three moat-map public surfaces are structurally
disjoint from OCI: pip and brew keys are **bare hex** (`[0-9a-f]`), which can
never contain a `:`, so they can never equal an OCI wire key `sha256:<hex>`.
npm tarballs are per-tenant (not `_public`). npm **metadata** lives in a
separate D1 KV table (`NpmMetaKv`, `npm.rs:184-203`), not the `adapter_cache_map`
the OCI read joins, and even as a string `npm:meta:<pkg>` cannot equal
`sha256:<64hex>`. Therefore **no non-OCI surface can create the colon-form map
row an OCI read resolves**, and symmetrically an OCI write's colon key is never
read by a bare-hex surface lookup. The CAS content layer is
blake3-content-addressed per namespace (`adapter_cache.rs`), so identical bytes
dedup safely and distinct bytes get distinct addresses. **Refutation attempt:**
can a malicious pip/brew client forge a colon key? No — pip's key is
`sha256(bytes)` (adapter-verified) and brew's is `blake3(path)`; both are
hex-encoders that cannot emit a colon. Holds. The colon is the partition.

## Surface 5 — revocation (WP-F) completeness

**Proof of safety (OCI path).** Revoke orders the durable
`public_blocklist` INSERT **first** (linearization point,
`public_revoke.rs:328-337`; migration `0097`), then deletes the map rows by
`(namespace='_public', content_hash)` (`:532`), audits, then best-effort R2
delete. Enforcement is layered (`migrations/d1/0097_public_blocklist.sql`):

- **Read-guard** — the `_public` map lookup joins `NOT EXISTS
  (public_blocklist)` in the **same** statement (`adapter_cache.rs:85-91`), so
  there is no map-read→blocklist-read TOCTOU. OCI reads traverse this
  (container D1), so a revoked digest is dead **immediately** on the OCI path.
- **Write-guard triggers** — `trg_public_blocklist_block_insert/_update`
  RAISE(ABORT) on any `_public` map (re-)pointing at a blocklisted content_hash
  (`0097.sql`). So tenant re-push (`oci.rs:594`) and mirror re-promote
  (`public_mirror.rs:359`) both **abort at the DB** — a race cannot re-populate.
- **Resolvability for OCI.** revoke-by-`upstream_digest` canonicalizes then
  resolves via `url_hash = OciDigest::to_wire()`
  (`public_revoke.rs:437-440`, SQL `:548-549`) — exactly the wire string the OCI
  writer stored, so an OCI `_public` row is always resolvable; an unresolvable
  digest fails **LOUD** (not a silent 200), and a bare 64-hex is refused as
  ambiguous (`:278-296`). Blast radius is content_hash-global by design
  (residual open #3).

**Refutation attempt:** orphan R2 bytes if the map-INSERT trigger aborts after a
CAS write — possible, but unreachable (no map row ⇒ no content_hash resolution ⇒
never served, and blocklisted regardless). GC concern, not a security hole.

**Finding F-1 (MEDIUM — brew/pip edge, pre-existing, NOT an OCI-flip blocker).**
`EDGE_PUBLIC_READ="serve"` is live in prod (`wrangler.toml:289,697,833,978,1117`)
and serves brew/pip `_public` cache HITs **from the edge, bypassing the
container** (`worker/src/index.ts:3609-3611`, gated to
`routeKind === "brew" || "pip"` — **OCI is excluded**). The edge caches a
positive `url_hash→content_hash` verdict for `PUBMAP_KV_TTL_S = 60`
(`worker/src/lib/edge_public_read.ts:190`) and only collapses the revocation
window to seconds if a content_hash-keyed `pubblock:<hash>` KV marker is written
(`:196-203`). That marker is written by the Worker revoke seam **only when the
request body carries a bare 64-hex `content_hash`** (`index.ts:2357-2373`,
regex `/^[0-9a-f]{64}$/`). But the documented incident path revokes by
`upstream_digest: "sha256:…"` (`public_revoke.rs:229-235`), whose body has **no**
`content_hash` field — so `writePublicBlocklistKv` never fires and the edge
falls back to the ≤60 s map-cache window (the code's own `catch` comment admits
this, `index.ts:2370-2373`). Net: during a live brew/pip poisoning incident, a
revoke-by-upstream-digest keeps the poisoned bytes edge-serving for up to ~60 s
after the container authoritatively revoked.
- **Why not an OCI-flip blocker:** OCI `_public` reads are never edge-served
  (the gate excludes OCI), so post-flip OCI revocation is immediate via the
  container D1 read-guard.
- **Exact fix:** add the resolved `content_hash` to `PublicRevokeResponse`
  (`public_revoke.rs:245-255`) and have the Worker seam mark the edge from the
  **response** (which is authoritative for both revoke spaces) instead of parsing
  it from the request body. Recommended before leaning on fast public revoke as
  the brew/pip incident control.

## Surface 6 — bearer-TTL window (Open-Q4)

**Finding F-3 (LOW / accepted).** An already-minted bearer can read `_public`
(and its per-tenant namespace) for its full TTL after tenant suspend/erase — no
per-request suspend check on the read path. For `_public` specifically the
content is **public, cross-tenant-shared base-layer bytes** (alpine, etc.), so
continued reads are not a confidentiality breach; the only effect is ≤TTL of
un-metered public reads by a suspended tenant. Acceptable for launch; if the
owner wants it bounded, cap the bearer TTL or add a per-request suspend check
(owner decision, per contract §OWNER GATES). Not a flip blocker.

## Surface 7 — quota / $-ceiling on uncapped `_public`

**Proof of safety.** `_public` writes seed `Some(0)` (uncapped) and accrue
`bytes_used` as a COGS meter that never rejects
(`byte_accounting.rs:611,795-805`). A tenant can route bytes to `_public`
**only** when `routes_to_public` fires, i.e. the digest is `is_allowlisted`
(`oci.rs:589`) — everything else goes per-tenant + charged (`:592`). The
allowlist is the finite, owner-pinned base-layer set (deny-all until WP-E), and
writes are content-addressed/idempotent (`oci.rs` inc6 tests
`:1736-1760`), so a tenant can add at most `|allowlist|` distinct blobs — not
unbounded storage, and no path to falsely reject another tenant (the shared
meter never rejects). No uncapped-DoS. Holds.
