# B-069 admin UI E2E handoff

The nine catalog journeys under `apps/admin-ui/playwright/e2e` are executable
and no longer deferred with `test.fixme`. The legacy Playwright configuration
uses the existing route warm-up and one worker so a shared Next dev server does
not expose transient route-tree 404s.

The suite uses only the test-mode session cookie and the shipped same-origin
fixture API. It does not change production auth, router, consent, or DSR
implementation. The behavior assertions intentionally preserve shipped safety
boundaries:

- consent capture and withdrawal remain 404 while the consent ledger endpoint
  is retired;
- DSR access and erasure remain in the loading/missing-tool state and never
  claim a receipt without real Clerk token/profile wiring;
- audit viewer exposes the fixture's Merkle mismatch, while dual approval
  rejects requestor self-approval and accepts an independent approver;
- locale and accessibility checks cover the translated, authenticated paths.

The workflow fails if any of these named journeys regresses to `test.fixme`.

The two intentional consent 404s are now observable rather than inferred from
status alone: each route owns a segment-local `not-found.tsx` with a distinct
retirement marker. The warm-up includes all B-069 non-retired routes and these
two consent paths; it accepts a consent 404 only when the matching marker is in
the response body. A generic Next route-tree 404 therefore remains a warm-up
failure, while the shipped retired status is preserved.
