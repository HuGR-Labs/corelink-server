# DPA and privacy-notice correction package — v1.0.1 draft

This is a counsel-ready drafting aid for B-035 and B-154. It is not an
executed amendment, does not supersede any `v1.0.0` file, and must not be
linked as the current click-through or notice. The historical `v1.0.0` bytes
remain unchanged until counsel approves a versioned replacement and the owner
executes any required customer notice or addendum.

## Truthful replacement language

Use this sentence in the three DPA locales, the EU SCC annex, and the
sub-processor commitments document:

> Encryption in transit uses a TLS 1.2 minimum; TLS 1.3 is negotiated when
> supported by the connecting client. The service does not promise a TLS 1.3
> floor unless the deployed edge configuration is raised and compatibility is
> re-validated.

Use the following localized equivalent in each privacy notice's security
section:

> Encryption in transit (TLS 1.2 minimum; TLS 1.3 negotiated when supported).

## Capability correction required by B-154

Where the current DPA says audit events are retained in R2 with Object Lock,
replace it with:

> Audit events are retained in the append-only, tamper-evident audit chain.
> Cloudflare R2 does not provide an S3 Object Lock implementation in the
> launched path, so this document makes no Object Lock or WORM-mode promise.
> Retention and erasure follow the deployed audit-chain and provider-retention
> controls described in the current security documentation.

Where the current DPA describes Enterprise BYOK as available, replace it with:

> BYOK and its kill-switch are future-state capabilities and are not enabled
> or provisioned in the launched CoreLink data plane. No BYOK latency SLO is
> included unless a separately approved production enablement and current
> evidence exist.

## Approval gate

Before publication, external counsel must approve the text, assign the final
