## W-F7 — CAS true per-tenant residency

**Decision (pinned):** route every CAS object to the R2 bucket of the **owning tenant's
`primary_region`**, not the serving env's region. Map (lead-pinned in the design doc):

| `tenant.primary_region` | bucket |
|---|---|
| `enam` / `wnam` | `corelink-cas-iad` |
| `weur` / `afr`  | `corelink-cas-lhr` |
| `sam`           | `corelink-cas-sam` |
| `apac`          | `corelink-cas-nrt` |

(`corelink-cas-{iad,lhr,sam,nrt,syd}` already provisioned. Public deterministic deps stay in the
global `corelink-cas-prod`.)

**Implementation:**
1. `fn cas_region_for_primary_region(&str) -> &'static str` (the map above; unknown → documented
   default `iad`, log a warn). Pure fn → property-test it.
2. The CAS read/write path resolves the tenant's `primary_region` (already on the request path — the
   same value `trg_blob_meta_region_match_insert` checks) and selects the bucket via the map, instead
   of the single `R2_CAS_REGION`. The container already holds S3 creds for all regions (cross-region
   write OK — correctness > the rare geo-mismatch hop).
3. Mirror onto AC if cheap; else scope AC to a follow-up.

**Gate:** invariant test — a `weur` tenant writes to `corelink-cas-lhr`, never `iad`; round-trips;
storage region == `blob_meta.region`. (Closes task #29 / the Schrems II residency risk.)

## W-F3 — in-container PAT re-verify (defense-in-depth)

**Decision:** wire `adapter_pat::PatVerifier` onto the native CAS/AC/Bazel/Turbo plane so the
CONTAINER independently re-verifies the inbound PAT (not merely trusting the Worker-injected,
header-stripped `x-corelink-tenant-id`). Resolve the tenant from the re-verified PAT and **assert it
matches** `x-corelink-tenant-id`; mismatch → reject. Two independent failures now required to cross a
tenant boundary; also closes any future Worker-side regression.

**Implementation:** a shared gate (mirror the cargo/brew/npm/pip `resolve_with_capability` pattern
from wave-1 F27) applied to the 4 native route groups. Reuse the existing `PatVerifier` (already
constructed for introspect). The Worker stays the first gate.

**Gate:** test — a request whose PAT resolves to tenant A but carries `x-corelink-tenant-id: B` →
rejected; matching → served.

## W-F4 — internal-auth hardening (3 parts)

Root cause: ONE shared, internet-reachable secret (`CORELINK_INTERNAL_AUTH_KEY`) gates all of
`/_internal/*` (mint, dsr, cas-erase). Leak = any-tenant admin-PAT minting.

- **W-F4a — per-consumer secrets.** Split into purpose-scoped secrets:
  `CORELINK_INTERNAL_MINT_KEY` (pat/mint), keep `CORELINK_INTERNAL_AUTH_KEY` for the rest, onboarding
  /tier-select gets its own. Tight blast radius per leak. (`FABRIC_INTROSPECT_AUTH_KEY` already split
  in wave-1 — same pattern.) **Owner-gated:** provision the new secret values (`wrangler secret put`).
- **W-F4b — per-tenant authz on mint.** `/_internal/pat/mint` must verify the caller is authorized
  for the *specific* tenant it mints for (not just "holds the shared secret"). Sequence after F4a.
- **W-F4c — Service-Binding-only `/_internal/*`.** signup-worker → this Worker internal calls move to
  a CF **Service Binding** (`[[services]]`, worker-to-worker, never public internet) instead of a
  public `fetch(corelink-api/_internal/...)`; then the public `/_internal/*` route is removed.
  The runners introspect (`/internal/v1/auth/introspect`) stays public (FABRIC-gated, the only legit
  external internal caller). **Sequencing (no outage window):** binding live BEFORE removing the
  public route. **Owner-gated:** `wrangler.toml [[services]]` + signup-worker deploy coordination.

**Gate:** after F4c, `/_internal/pat/mint` is NOT publicly routable (curl from internet → 404);
service-binding call still mints; a wrong/foreign tenant on mint → rejected (F4b).

## Sequencing & ship

1. Land wave-1 (followups `7cbda5ca`) + §B on main.
2. Parallel: W-F7, W-F3, W-F4a (file-disjoint). Then W-F4b (after F4a).
3. W-F4c last (owner provisions `[[services]]` + per-consumer secrets; coordinate binding-before-route-removal).
4. **One container rebuild** carrying F7+F3+F4a/b → pin prod (deploy step). F4c is a worker+wrangler deploy.

**Owner-gated checklist:** per-consumer secret values (F4a) · `[[services]]` binding + signup-worker
coordination (F4c). Everything else is decide+execute by the lead.
