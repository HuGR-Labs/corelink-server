## Ledger, operating contract, and non-negotiable gates

Open IDs covered exactly once by the contracts below are: B-097, B-110 and
B-111 (3 total). All
other IDs in B-091..B-130 are `done` or `parked` on the D03 base. The verifier
derives this population from `BACKLOG.md`.

Every executor must read `CLAUDE.md`, `docs/internal/DELEGATION-WP-CONTRACT.md`, the
current stanza of its B-ID, the named source/tests, and the OKF context of each code file
before modifying anything.  It works in a dedicated worktree, may edit **only** the
allowlist in its contract, and halts when an omitted file is necessary.  It returns a card
with base/head SHA, changed paths, commands and results, population/control counts,
negative/mutation evidence, residual risk, blocker, and a proposed status change.  The
lead—not the executor—decides cross-contract policy, backlog status, merge, and conflicts.

All code WPs require a behavior test plus a mutation that makes it fail for the intended
reason; a zero/empty/truncated/unparseable population is `INDETERMINATE`, never success.
Run the applicable focused suite, `python3 scripts/validate_okf.py` for cited code,
the relevant BACKLOG verifier if the lead later changes BACKLOG, secret checks, changelog
policy, DCO sign-off, and `bash scripts/pre-merge-gate-check.sh <PR>` before handoff.
Merge is exclusively `bash scripts/pre-merge-gate-check.sh --merge <PR>` by the lead.

Shared files are serial spines, not parallel ownership: memory/body budgets (B-093),
release workflows (B-091/B-112/B-113), OpenAPI/routes (B-116--B-120/B-130), phase timing
(B-102--B-109/B-122/B-129), OKF (B-123/B-124/B-126), and audit drain data (B-125/B-127).
`BACKLOG.md` and `CHANGELOG.md` are reserved for the lead's final integration commit.

The compact contracts below deliberately inherit the following **explicit fields**; this
is part of every WP, including owner-only and measurement WPs, rather than an unstated
convention:
