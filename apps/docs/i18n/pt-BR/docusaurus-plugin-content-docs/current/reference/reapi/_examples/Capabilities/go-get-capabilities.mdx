# Go — `Capabilities.GetCapabilities` não está disponível

`Client.Capabilities` existe na superfície de tipos do SDK, mas não há
nenhum endpoint de servidor por trás dele. A tabela de rotas da REAPI v2
(`crates/corelink-container/src/routes/bazel_v2.rs`) monta exatamente
cinco rotas — leitura de CAS, escrita de CAS, leitura de AC, escrita de
AC, e `findMissingBlobs` — e nenhuma delas é uma superfície de
capabilities. `Capabilities` não faz nenhuma chamada de rede; ele retorna
o `ServerCapabilities` zero-value e um erro explicando o motivo.

## Código

```go
package main

import (
    "context"
    "fmt"
    "os"

    corelink "go.corelink.humangr.com/corelink-go"
)

func main() {
    ctx := context.Background()
    client, _ := corelink.NewClient(corelink.Config{
        Endpoint: "https://corelink-api.humangr.com",
        PAT:      os.Getenv("CORELINK_PAT"),
    })
    defer client.Close()

    _, err := client.Capabilities(ctx)
    fmt.Println(err)
}
```

## Saída esperada

```text
corelink: no REAPI Capabilities endpoint exists on this server (bazel_v2.rs mounts only CAS read/write, AC read/write, and findMissingBlobs); use Client.Health for a readiness check instead
```

## O que usar em vez disso

Use `Client.Health` para uma checagem de prontidão (veja o exemplo
[Health · Check](../Health/go-check.mdx)). Para escolher uma função de
digest sem um endpoint de negociação, veja
[pick a digest function](./go-pick-digest.mdx).
