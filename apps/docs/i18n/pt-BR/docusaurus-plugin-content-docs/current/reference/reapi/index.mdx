# REAPI v2 reference

O CoreLink implementa um subconjunto compatível na fiação e com escopo por
tenant de [`bazelbuild/remote-apis @ v2.12.0`](https://github.com/bazelbuild/remote-apis/tree/v2.12.0).
Bazel 6+, Buck2 e qualquer outro cliente REAPI v2 se conectam **sem
mudança de código** — apenas o endpoint de cache e o PAT diferem.

## Autenticação

Toda RPC carrega um PAT no cabeçalho de metadados
`Authorization: Bearer <pat>`. O formato canônico do token é:

```
corelink_<env>_<token_id>.<random_secret>.<hmac_sig>
```

O placeholder usado neste site — `corelink_pat_0123456789ABCDEF.AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA.BBBBBBBBBBBBBBBBBBBBBA` — é
intencional e nunca deve aparecer em produção.

## Páginas de serviço geradas automaticamente

As páginas desta seção são regeneradas a partir dos arquivos `.proto`
vendorizados por `pnpm docs:gen`. O CI garante zero drift entre o proto e
o MDX renderizado (`pnpm docs:gen:check`) em cada PR.

Navegue pelo índice gerado para ver todos os serviços da build atual.

## Exemplos de código manuais

Para cada serviço, exemplos escritos à mão em quatro linguagens vivem em
`_examples/<Service>/`:

- **Python** (`corelink-py`)
- **Go** (`corelink-go`)
- **Node / TypeScript** (`@corelink/client`)
- **CLI** (`corelink`)

Os exemplos cobrem os fluxos mais comuns: autenticação por PAT,
`BatchUpdateBlobs`, `BatchReadBlobs`, `FindMissingBlobs`,
`Capabilities.GetCapabilities`, `ByteStream.Read`, `ByteStream.Write`, e
sondagem de saúde (health).

## Modelo de erros

O CoreLink mapeia todo código de status da REAPI v2 para um identificador
estável de `error_taxonomy` (`COR_CAS_*`, `COR_AUTH_*`, `COR_QUOTA_*`).
Veja [error taxonomy](../../tutorial/06-verify-cache-hit.mdx#troubleshooting)
para os casos mais comuns.
