# Bazel remote cache in 5 minutes

CoreLink implements the **Bazel Remote Execution API v2 (REAPI v2)** cache as a
ByteStream REST scheme:

```text
https://corelink-api.humangr.com/bazel/v2/<your-tenant-id>/blobs/<hash>/<size>
```

The `<instance>` path segment is your tenant UUID, and the endpoint is backed by
the same per-tenant R2 blobs the native CAS serves.

:::tip Stock `bazel --remote_cache` works today — no REAPI client needed
The **stock-HTTP alias** `https://corelink-api.humangr.com/bazel/cache` is live.
It serves exactly what vanilla Bazel emits: `GET`/`PUT` on `/cas/<sha256>` and
`/ac/<sha256>`, with no `:instance` segment and no `:size`. Your tenant is
**not** in that URL — it is resolved by the host-scoped credential helper from `CORELINK_PAT`.

```ini
build --remote_cache=https://corelink-api.humangr.com/bazel/cache
build --credential_helper=corelink-api.humangr.com=%workspace%/.bazel/corelink-credential-helper.sh
build --remote_upload_local_results=true
```

Both surfaces are live and back onto the same per-tenant R2 blobs; use the
`/bazel/v2` ByteStream config below if your client speaks REAPI.
:::

## Prerequisites

- `CORELINK_PAT` exported ([step 2](./02-first-pat)) and your tenant UUID.
- Stock Bazel (for `/bazel/cache`) or a REAPI/ByteStream-compatible client
  (for `/bazel/v2`). Either works.

## Reference configuration

Here is a reference `.bazelrc` config. It points Bazel's REAPI instance at
your tenant:

```ini
# Point at the CoreLink REAPI v2 endpoint (the /bazel/v2 prefix is required).
build --remote_cache=https://corelink-api.humangr.com/bazel/v2

# Your tenant UUID becomes the REAPI :instance path segment.
build --remote_instance_name=${CORELINK_TENANT}

# Authenticate with your PAT. The Cloudflare Worker validates the bearer token
# and injects the tenant header before the request reaches the cache.
build --credential_helper=corelink-api.humangr.com=%workspace%/.bazel/corelink-credential-helper.sh

build --remote_timeout=30s
build --remote_upload_local_results=true
```

Export both values before building:

```bash
export CORELINK_PAT="corelink_pat_0123456789ABCDEF.AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA.BBBBBBBBBBBBBBBBBBBBBA"
export CORELINK_TENANT="<your-tenant-id>"
```

## Verify

Run your build twice — the second run should read blobs back from CoreLink
rather than recompiling. Inspect Bazel's execution log
(`--execution_log_json_file`) for `remoteCacheHit: true` entries to confirm.
