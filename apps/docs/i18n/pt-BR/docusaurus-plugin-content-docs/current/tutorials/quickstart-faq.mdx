# Quickstart FAQ

Fifteen questions every new CoreLink user asks during or right after
the [10-minute quickstart](./quickstart-10min.mdx). If your question
isn't here, jump to [Support](#15--how-do-i-get-help-if-i-am-stuck).

---

## 1 — Does my free tenant expire?

**No.** The **Free** tier is free forever and never asks for a card
(see [/pricing](/pricing)). It is a real tenant, not a scratch one:
nothing is garbage-collected on a clock. What is bounded is the plan's
own allowance — cache size, monthly requests, and audit retention —
see question 8.

## 2 — Does free-tier usage trigger billing?

**No.** The Free tier carries no payment method, so it cannot be
charged; when you exhaust its allowance the cache returns quota errors
rather than an invoice. Billing only starts when you upgrade to a paid
plan and attach a payment method or PO. You can finish the quickstart,
evaluate for as long as you like, and never enter a credit card.

## 3 — How do I move from Free to a paid plan?

You upgrade in place — there is no tenant-to-tenant migration and no
new tenant ID. Pick a plan on [/pricing](/pricing), then complete
Stripe checkout at
[humangr.com/corelink/en/upgrade](https://humangr.com/corelink/en/upgrade)
(~2 min). Your tenant, its blobs, and its audit history are unchanged;
only the plan allowances move.

## 4 — Which regions can I deploy to?

GA regions at launch: **`us-east-1`** (Cloudflare IAD), **`us-west-2`**
(LAX), **`eu-west-1`** (DUB), **`ap-southeast-1`** (SIN). The
control-plane is global; data-plane is regional and **never crosses
boundaries** without an explicit cross-region replication policy
(Lighthouse+). Free-tier tenants are provisioned in the geographically
closest region to your sign-up IP.

## 5 — Can I use BYOK on the Free tier?

**No** — BYOK (Bring Your Own Key) is an Enterprise-tier control that
requires your own AWS KMS / GCP Cloud KMS / Azure Key Vault / HashiCorp
Vault key reference. Free-tier tenants use the CoreLink-managed
envelope key (still XChaCha20-Poly1305 AEAD, per-tenant DEK). To trial BYOK,
contact [enterprise@humangr.com](mailto:enterprise@humangr.com) for
a 30-day BYOK evaluation tenant.

## 6 — Which languages have official SDKs at GA?

Four canonical SDKs ship at GA, all wrapping the single Rust
`corelink-client-verify` truth (no per-language hash drift):

| Language | Package | FFI surface |
| --- | --- | --- |
| **Rust** | `corelink-client-verify` (crates.io) | native |
| **Python** | `corelink-py` (PyPI) | PyO3 |
| **Go** | `go.corelink.humangr.com/corelink-go` | cgo |
| **JS / TS / Browser** | `@corelink/client` (npm) | wasm-bindgen |

## 7 — Language SDK roadmap beyond GA?

Post-GA priority order (subject to demand signal):

- **Java / Kotlin** (Q3 post-GA) — JNI binding over the Rust core.
- **Ruby** (Q4 post-GA) — FFI binding.
- **C# / .NET** (Q4 post-GA) — P/Invoke binding.
- **Swift** (community-driven; no committed date).

File a +1 on the [SDK request issue tracker](https://github.com/HumanGuardrail/corelink-server/issues?q=label%3Asdk-request)
to influence priority.

## 9 — Do I need a separate PAT per environment?

Yes — PATs are tenant-scoped and environment-scoped. The token format
`corelink_<env>_t_xxx.xxx.xxx` makes the env explicit (`dev`,
`staging`, `prod`). Mixing a `prod` PAT against a `staging`
tenant is rejected with `COR_AUTH_TENANT_MISMATCH` at the edge. You
can mint as many PATs per tenant as you want; revocation is per-token.

## 10 — How do I rotate or revoke a PAT?

In the admin UI: **Settings → Tokens → Revoke**. Revocation propagates
globally in **&lt; 60 seconds** (FM-061 rotation drill measures the
actual P95). Revoked tokens immediately fail with
`COR_AUTH_PAT_REVOKED` even if cached client-side. For programmatic
rotation see the [REST API](../reference/api/openapi.mdx) `/v1/pats`
endpoints — the canonical pattern is "create new → swap into
secrets-store → revoke old".

## 11 — Why does `--pat` not work on the CLI?

By design — security control **CTRL-CRED-001**. PAT flags would leak
into shell history and process listings (`ps aux`). The CLI reads from:

1. `CORELINK_PAT` environment variable (recommended), or
2. `~/.corelink/config.toml` (`corelink config set auth.pat …`).

Passing `--pat` exits with code 2 and a clear error pointing here.

## 12 — Does `corelink get` actually verify the bytes?

Yes — client-side BLAKE3 re-hash is **default-on** (control
**CTRL-CAS-002**). A mismatch raises `COR_CAS_DIGEST_MISMATCH` and the
process exits non-zero before the bytes touch your filesystem. To
*opt out* (not recommended) construct an SDK client with
`client_verify=False`; the CLI does not offer an opt-out flag.

## 13 — How do I see audit events programmatically?

Three paths:

- **CLI** — `corelink ls --tenant <id>` + `corelink stat <digest> --output json` gives per-blob first-seen / last-seen / access counts.
- **REST** — `GET /v1/audit/events?since=2026-05-15T00:00:00Z` with your PAT (see [REST reference](../reference/api/openapi.mdx)).
- **Streaming** — Enterprise tier supports webhook delivery to your SIEM (Datadog, Splunk, Sumo, custom HTTPS endpoint) with HMAC-signed payloads.

Free-tier tenants expose the same REST surface; only the retention
window differs.

## 14 — What is the CLI's `doctor` subcommand for?

`corelink doctor` runs 8 diagnostic checks: network reachability, PAT
validity, tenant existence, BYOK key reachability (if configured),
region health, quota headroom, client-verify wiring, and config-file
readability. It's the **first command to run when something's
broken** — copy its `--output=json` output into a support ticket and
we can usually triage without further questions.

## 15 — How do I get help if I am stuck?

Support channels, fastest first:

- **GitHub Discussions** — [github.com/HumanGuardrail/corelink-server/discussions](https://github.com/HumanGuardrail/corelink-server/discussions) for design questions + roadmap.
- **GitHub Issues** — [github.com/HumanGuardrail/corelink-server/issues](https://github.com/HumanGuardrail/corelink-server/issues) for bugs (please include `corelink doctor --output=json`).
- **Email** — [support@humangr.com](mailto:support@humangr.com) for billing or account issues. **Enterprise plans** include a dedicated Slack Connect channel + a 4-hour SEV-1 response SLA.

For security disclosures see [`SECURITY.md`](https://github.com/HumanGuardrail/corelink-server/blob/main/SECURITY.md) — **do not** open public issues for vulnerabilities.
