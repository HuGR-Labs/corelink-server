# Quickstart — cadastro até o primeiro cache hit em 10 minutos

**Objetivo:** cadastre-se, instale a CLI, verifique a conectividade com
`corelink doctor`, configure seu repositório Bazel e veja os cache HITs
aparecerem na segunda build.
**Orçamento total: ≤ 10 minutos para um engenheiro experiente.**

Todos os comandos são canônicos e verificados contra o MVP do `corelink-cli`
(commit [`71d7f6a9`](https://github.com/HumanGuardrail/corelink-cli/commit/71d7f6a9),
subcomandos: `ping`, `bazel-init`; `doctor` chega na próxima release da CLI —
a documentação reflete o UX planejado antes do binário).

:::tip Sem cartão de crédito
Uma conta iniciante é gratuita até 10 GB. O wizard de cadastro provisiona
seu tenant, região e um PAT inicial no servidor — sem etapa de cobrança.
:::

---

## Antes de começar

- **Bazel 7+** instalado e no `PATH`
- Um navegador para o cadastro (Clerk, aceita Google / GitHub / e-mail)
- macOS, Linux ou Windows (WSL2 recomendado para Windows)

---

## Passo 1 — Cadastre-se <span style={{color:"var(--ifm-color-emphasis-600)"}}>(~1 min)</span>

1. Abra **[https://humangr.com/corelink](https://humangr.com/corelink)** no navegador.
2. Conclua o wizard de cadastro em 2 passos (escolha sua região primária — `ord`
   (US-Central) é um bom padrão para a maioria dos times).
3. O wizard leva à página **`/welcome`**, onde seu PAT inicial é exibido
   **uma única vez**. Copie-o antes de fechar a aba.
   Formato: `ct_live_xxx…xxx`

:::warning Copie seu PAT em /welcome — ele é exibido apenas uma vez
Se fechar a aba sem copiar, regenere em **Settings → Access tokens → Regenerate**.
Nunca cole um PAT real em docs compartilhados, Slack ou código-fonte.
:::

---

## Passo 2 — Instale a CLI <span style={{color:"var(--ifm-color-emphasis-600)"}}>(~1 min)</span>

Execute o script de instalação. Passe o PAT copiado no Passo 1 e a região escolhida.

```bash
curl -fsSL https://corelink-get.humangr.com | sh -s -- \
  --token=ct_live_xxx…xxx \
  --region=ord
```

O script:
1. Detecta sua plataforma (macOS arm64/amd64, Linux amd64/arm64).
2. Baixa o binário estático `corelink` para `/usr/local/bin`
   (fallback para `~/.local/bin` se `/usr/local/bin` não for gravável).
3. Escreve `~/.corelink/config.toml` com seu PAT e endpoint.
4. Executa `corelink whoami`, que verifica o PAT **e** grava o tenant ID
   resolvido nesse mesmo arquivo (o instalador não sabe qual é o seu).

Saída esperada:

```text
Downloading CoreLink CLI from https://github.com/HuGR-Labs/corelink-cli/releases/latest/download/corelink-darwin-arm64 ...
tenant_id:    <your-tenant-id>
token_prefix: corelink_pat_3f9a…
route_kind:   pat
Next: cd into your Bazel repo, run: corelink bazel-init
```

Se `corelink whoami` imprimir seu tenant ID, avance para o Passo 3.

---

## Passo 3 — `corelink doctor` <span style={{color:"var(--ifm-color-emphasis-600)"}}>(~30 s)</span>

`corelink doctor` executa 8 verificações de conectividade e autenticação:

```bash
corelink doctor
```

Saída saudável:

```text
CHECK              STATUS   LATENCY             ERROR_CODE   NEXT_ACTION
----------------------------------------------------------------------------------------------------
network            ok            12ms
auth               ok            31ms
storage_write      ok            88ms
storage_read       ok            41ms
byok               skip           n/a                        BYOK not configured; set auth.byok_enabled=true and KMS credentials to enable.
region             skip           n/a
quota              ok            27ms
client_verify      ok             n/a

All checks passed (6 ok, 2 skipped).
```

Latências variam. `region` sempre reporta `skip` — nenhuma rota pública expõe
a região primária de um tenant — e `byok` é pulado a menos que você tenha optado
por BYOK. Portanto `6 ok, 2 skipped` é o resultado saudável, não um alerta.

Se alguma verificação mostrar `✗`, a saída inclui uma dica de correção.
Os problemas mais comuns estão na seção [Solução de problemas](#solucao-de-problemas) abaixo.

:::note
`corelink whoami` é a checagem mais leve — verifica a autenticação e resolve seu
tenant sem tocar no cache. `corelink doctor` roda as 8 checagens, incluindo uma
escrita/leitura real na CAS, então exige um PAT de leitura e escrita.
:::

---

## Passo 4 — `corelink bazel-init` <span style={{color:"var(--ifm-color-emphasis-600)"}}>(~30 s)</span>

Entre na raiz do seu repositório Bazel e execute:

```bash
cd /caminho/para/seu-repo-bazel
corelink bazel-init
```

`corelink bazel-init` adiciona as linhas de remote-cache ao `.bazelrc`
e escreve um arquivo `.corelink/credentials` (modo `0600`) com escopo
para a raiz do repositório:

```text
corelink bazel-init: appended to .bazelrc:
  build --remote_cache=grpcs://cas.corelink.humangr.com:443
  build --remote_header=x-corelink-tenant=acme-prod
  build --remote_header=authorization=Bearer ${CORELINK_PAT}
  build --remote_upload_local_results=true
corelink bazel-init: wrote .corelink/credentials (mode 0600)
```

`bazel-init` é **idempotente**: executá-lo uma segunda vez detecta a
linha marcadora existente no `.bazelrc` e encerra com `0` sem duplicatas.

:::tip Commit .bazelrc, não .corelink/credentials
Adicione `.bazelrc` ao git para que a equipe compartilhe a configuração.
Adicione `.corelink/credentials` ao `.gitignore` — o arquivo contém
um PAT por desenvolvedor.
:::

---

## Passo 5 — Primeira build (cache frio) <span style={{color:"var(--ifm-color-emphasis-600)"}}>(~3 min)</span>

Execute a build Bazel pela primeira vez. Isso popula o cache remoto.

```bash
bazel build //...
```

Esta é a execução **fria** que envia seus artefatos para o cache.

---

## Passo 6 — Segunda build (cache HITs) <span style={{color:"var(--ifm-color-emphasis-600)"}}>(~1 min)</span>

Execute a mesma build novamente:

```bash
bazel build //...
```

Desta vez o Bazel busca do cache CoreLink em vez de recompilar:

```text
INFO: 42 processes: 38 remote cache hit, 4 internal.
```

Esse contador `remote cache hit` é o **evento de ativação** — seu
primeiro cache hit CoreLink bem-sucedido.

:::note Por que compilar duas vezes?
A primeira build popula o cache (MISS → UPLOAD). A segunda lê dele
(HIT → DOWNLOAD). O cache é mais valioso no segundo run do seu pipeline
de CI e para colegas que compilam o mesmo commit.
:::

## Solução de problemas {#solucao-de-problemas}

### Incompatibilidade de região — latência alta ou erros gRPC `UNAVAILABLE`

**Sintoma:** RTT > 200 ms no `corelink doctor` passo 6, ou Bazel registra `UNAVAILABLE`.

**Correção:**
```bash
corelink config set defaults.region <região-correta>
corelink bazel-init --force
```

Regiões disponíveis: `ord` (US-Central), `iad` (US-East), `lhr` (EU-West),
`nrt` (AP-Northeast), `syd` (AP-Southeast).

### Token ausente — `UNAUTHENTICATED` em todas as ações Bazel

**Sintoma:** Bazel registra `UNAUTHENTICATED`.

**Correção:** verifique `echo $CORELINK_PAT` ou defina via config:

```bash
corelink config set auth.pat "ct_live_xxx…xxx"
```

### Aviso de linha duplicada no `.bazelrc`

**Sintoma:** `WARNING: Duplicate rc option: --remote_cache`.

**Correção:** remova as linhas duplicadas manualmente e confirme com `corelink doctor`.

### Verificação 8 do `corelink doctor` falha — `PERMISSION_DENIED`

**Sintoma:** `[8/8] tenant write permission  ✗  PERMISSION_DENIED`.

**Correção:** verifique o tenant ID e regenere o PAT com escopo `write` se necessário:

```bash
corelink config set defaults.tenant_id <seu-tenant-id>
```
