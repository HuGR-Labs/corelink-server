# Consulta e armazenamento no Action Cache

## Quando usar este guia

Você envolve um executor de testes orientado por JS (por exemplo, Jest, Vitest, Playwright) com uma
camada de cache de build e quer semântica de acerto/erro indexada por um digest de Action.

Se você só precisa do CAS bruto, veja
[02-upload-blob](./02-upload-blob) e
[03-download-blob](./03-download-blob).

## O payload do AC são bytes opacos

O CoreLink armazena um **payload de bytes `ActionResult` opaco** indexado por um digest de
action de 64 hex (`routes/ac.rs`). O SDK move esses bytes literalmente — você é dono da
codificação (por exemplo, uma mensagem `ActionResult` REAPI serializada, ou seu próprio manifesto
JSON referenciando blobs do CAS por digest). `actionCache.get` retorna um
`Uint8Array`; `actionCache.put` recebe um.

## Consulta

```typescript
import { ActionCacheMiss } from "@corelink/client";

async function getOrRun(actionDigest: string): Promise<Uint8Array> {
  try {
    const resultBytes = await client.actionCache.get(actionDigest);
    const manifest = JSON.parse(new TextDecoder().decode(resultBytes));
    return client.get(manifest.stdoutDigest); // fetch the referenced CAS blob
  } catch (e) {
    if (e instanceof ActionCacheMiss) {
      return runLocallyAndStore(actionDigest);
    }
    throw e;
  }
}
```

## Armazenamento

```typescript
async function storeResult(
  actionDigest: string,
  stdout: Uint8Array,
  exitCode: number,
): Promise<void> {
  const stdoutDigest = await client.put(stdout);
  const manifest = { stdoutDigest, exitCode };
  const bytes = new TextEncoder().encode(JSON.stringify(manifest));
  await client.actionCache.put(actionDigest, bytes);
}
```

## Imutabilidade e proteção contra envenenamento de cache

As entradas do AC são imutáveis por conteúdo: o servidor rejeita uma sobrescrita divergente de uma
`(tenant, action_digest)` existente com `409`, exposto como `ConflictError`. Um
novo armazenamento byte a byte idêntico é uma operação idempotente sem efeito.
