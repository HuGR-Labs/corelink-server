# Action Cache

## Quando usar este guia

Você quer armazenar em cache o resultado de uma ação de build — código de
saída, stdout, arquivos de saída — indexado por um digest da ação, e
consultá-lo antes de rodar a ação de novo.

## `Client.ActionCache()`

`corelink.Client` expõe o Action Cache da REAPI v2 através de
`Client.ActionCache()`, que retorna um `*corelink.ActionCacheClient` com
dois métodos:

```go
ac := client.ActionCache()

// Update stores an ActionResult for an action digest.
err := ac.Update(ctx, actionDigest, corelink.ActionResult{
    ExitCode: 0,
    OutputFiles: []corelink.OutputFile{
        {Path: "bin/app", Digest: outputDigest, IsExecutable: true},
    },
})

// Get returns a cached ActionResult, or corelink.ErrActionCacheMiss.
result, err := ac.Get(ctx, actionDigest)
```

`Update` grava em `PUT /bazel/v2/{instance}/blobs/ac/{hash}/{size}`; `Get`
lê do mesmo caminho. Ambos operam contra `Config.Instance` — defina-o na
`Config` que você passa a `NewClient` ao construir o cliente, da mesma
forma que você configuraria um nome de instância de remote-cache do Bazel.

## Lidando com um cache miss

Um miss não é um erro que você trata por string. Compare com o sentinel
usando `errors.Is`:

```go
result, err := ac.Get(ctx, actionDigest)
switch {
case errors.Is(err, corelink.ErrActionCacheMiss):
    result, err = runActionAndStore(ctx, ac, actionDigest)
    if err != nil {
        return err
    }
case err != nil:
    return fmt.Errorf("action cache lookup: %w", err)
}
```

## Codificação

O servidor armazena o payload do Action Cache como um blob de bytes
opaco — ele não o interpreta. `ActionCacheClient.Update` e `.Get` cuidam
da codificação por conta própria (um formato JSON privado), então
`ActionResult` percorre o ciclo de ida e volta por este SDK sem que você
precise escrever nenhum código de serialização. Um payload gravado por um
cliente diferente (o SDK JS/TS, ou uma chamada HTTP crua) usa sua própria
codificação e não será decodificado como um `ActionResult` aqui.
