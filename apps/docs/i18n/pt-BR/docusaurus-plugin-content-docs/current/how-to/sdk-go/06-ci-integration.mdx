# CI integration

## Quando usar este guia

Seu build é um projeto Go (ou seus smoke tests são escritos em Go) e você
quer o CoreLink como cache compartilhado sem sair chamando a CLI.

## GitHub Actions

```yaml
# .github/workflows/build.yml
jobs:
  build:
    runs-on: ubuntu-latest
    env:
      CORELINK_PAT: ${{ secrets.CORELINK_PAT }}
      GOPROXY: https://humangr.com/corelink/docs/goproxy,https://proxy.golang.org,direct
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-go@v5
        with:
          go-version: "1.22"
      - run: go get go.corelink.humangr.com/corelink-go@v0.1.0  # GOPROXY definido acima
      - run: go run ./ci/warm-cache
```

```go
// ci/warm-cache/main.go
package main

import (
    "context"
    "log"
    "os"

    "go.corelink.humangr.com/corelink-go"
)

func main() {
    ctx := context.Background()
    cli, err := corelink.NewClient(corelink.Config{
        Endpoint: "https://corelink-api.humangr.com",
        PAT:      os.Getenv("CORELINK_PAT"),
        TenantID: os.Getenv("CORELINK_TENANT"),
    })
    if err != nil {
        log.Fatal(err)
    }
    defer cli.Close()

    // Warm the cache with a real Put/Get round trip and fail the job on error.
    digest, err := cli.Put(ctx, []byte("ci-warm-cache-probe"))
    if err != nil {
        log.Fatalf("cache warm-up failed: %v", err)
    }
    if _, err := cli.Get(ctx, digest); err != nil {
        log.Fatalf("cache verify failed: %v", err)
    }
    log.Println("cache reachable")
}
```

## GitLab CI

```yaml
build:
  image: golang:1.22
  variables:
    CORELINK_PAT: $CORELINK_PAT  # masked
    GOPROXY: "https://humangr.com/corelink/docs/goproxy,https://proxy.golang.org,direct"
  script:
    - go get go.corelink.humangr.com/corelink-go@v0.1.0  # GOPROXY definido acima
    - go run ./ci/warm-cache
```

## CircleCI

```yaml
version: 2.1
jobs:
  build:
    docker:
      - image: cimg/go:1.22
    environment:
      CORELINK_PAT: $CORELINK_PAT
      GOPROXY: https://humangr.com/corelink/docs/goproxy,https://proxy.golang.org,direct
    steps:
      - checkout
      - run: go get go.corelink.humangr.com/corelink-go@v0.1.0  # GOPROXY definido acima
      - run: go run ./ci/warm-cache
```

## PATs por job

Emita você mesmo um PAT dedicado de CI — pela página **Keys** do dashboard
ou com `POST /v1/customer/keys` e o corpo `{"name": "...", "scopes": [ … ]}`
(veja [Security model](../../security.md)) — e injete-o via o secret store do
seu provedor de CI, como mostrado acima. Para revogá-lo, use
`POST /v1/customer/keys/{pat_id}/revoke`.

O corpo de criação aceita apenas `{name, scopes}`: não há campo de TTL, então
um PAT não expira sozinho — um token por pipeline significa emitir-e-revogar,
não um token com validade. Emitir um PAT com escopo de escrita também exige que
quem chama já tenha uma capacidade de escrita no cache; um token somente
leitura (`cas:r`) recebe `403`.
