# Autenticar a CLI

## Quando usar este guia

Você instalou o binário `corelink` (um único executável assinado para macOS,
Linux e Windows) e precisa executar qualquer comando, exceto `version`.

## Pré-requisitos

- Binário `corelink` no `$PATH`. Instale-o pelo seu gerenciador de pacotes ou
  baixe-o na página de releases do GitHub. Verifique a atestação SLSA antes do
  primeiro uso.
- Um PAT emitido em `https://humangr.com/corelink/en/customer/keys`.

## Recomendado: variável de ambiente

```bash
export CORELINK_PAT="corelink_dev_t_xxx.xxx.xxx"
corelink ls --tenant acme-corp
```

## Alternativa: arquivo de configuração

```bash
corelink config set auth.pat corelink_dev_t_xxx.xxx.xxx
corelink config set defaults.tenant_id acme-corp
```

O arquivo fica em `~/.corelink/config.toml` no macOS/Linux e em
`%APPDATA%\corelink\config.toml` no Windows. O modo do arquivo é imposto como
`0600` e o PAT é ocultado por `corelink config list`.

## Proibido: PAT como flag da CLI

```bash
# DO NOT DO THIS — the CLI exits 2 with an explicit security error.
corelink --pat=corelink_dev_t_xxx.xxx.xxx ls --tenant acme-corp
```

CTRL-CRED-001 proíbe a flag `--pat` porque os argumentos de processo vazam via
`ps`, histórico do shell e logs de CI. A CLI rejeita a flag antes de qualquer
outra análise.

## Verificar

```bash
corelink doctor --json | jq '.checks[] | select(.name=="auth")'
```

Esperado `status: "ok"`. Qualquer outro status é mapeado para um código
`COR_AUTH_*` com um link direto para o documento de próxima ação correto.
