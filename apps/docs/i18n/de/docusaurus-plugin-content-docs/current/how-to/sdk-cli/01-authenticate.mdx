# CLI authentifizieren

## Wann Sie diese Anleitung verwenden

Sie haben das `corelink`-Binary installiert (eine einzige signierte ausführbare
Datei für macOS, Linux und Windows) und müssen einen beliebigen Befehl außer
`version` ausführen.

## Voraussetzungen

- `corelink`-Binary im `$PATH`. Installieren Sie es über Ihren Paketmanager oder
  laden Sie es von der GitHub-Releases-Seite herunter. Überprüfen Sie die
  SLSA-Attestierung vor der ersten Verwendung.
- Ein PAT, erstellt unter `https://corelink-app.humangr.com/tokens`.

## Empfohlen: Umgebungsvariable

```bash
export CORELINK_PAT="corelink_dev_t_xxx.xxx.xxx"
corelink ls --tenant acme-corp
```

## Alternative: Konfigurationsdatei

```bash
corelink config set auth.pat corelink_dev_t_xxx.xxx.xxx
corelink config set defaults.tenant_id acme-corp
```

Die Datei liegt unter `~/.corelink/config.toml` auf macOS/Linux und unter
`%APPDATA%\corelink\config.toml` auf Windows. Der Dateimodus wird auf `0600`
erzwungen und der PAT wird von `corelink config list` unkenntlich gemacht.

## Verboten: PAT als CLI-Flag

```bash
# DO NOT DO THIS — the CLI exits 2 with an explicit security error.
corelink --pat=corelink_dev_t_xxx.xxx.xxx ls --tenant acme-corp
```

CTRL-CRED-001 verbietet das Flag `--pat`, weil Prozessargumente über `ps`, den
Shell-Verlauf und CI-Logs nach außen gelangen. Die CLI weist das Flag vor jeder
weiteren Auswertung zurück.

## Überprüfen

```bash
corelink doctor --json | jq '.checks[] | select(.name=="auth")'
```

Erwartet wird `status: "ok"`. Jeder andere Status wird einem `COR_AUTH_*`-Code mit
einem direkten Link zum passenden Dokument für die nächste Aktion zugeordnet.
