# Ein Blob hochladen

## Wann diese Anleitung verwenden

Sie haben ein `[]byte` und wollen es in den CoreLink-CAS persistieren.
`Put` berechnet den BLAKE3-Digest für Sie — es gibt in diesem SDK keine
Möglichkeit, clientseitig einen vorab berechneten Digest zu übergeben
(anders als `expected_digest=` bei `corelink-py`).

## Voraussetzungen

- Authentifizierung konfiguriert ([01-authenticate](./01-authenticate.mdx)).

## Minimalbeispiel

```go
import (
    "context"
    "os"

    "go.corelink.humangr.com/corelink-go"
)

func upload(ctx context.Context, cli *corelink.Client, path string) (string, error) {
    data, err := os.ReadFile(path)
    if err != nil {
        return "", err
    }
    digest, err := cli.Put(ctx, data)
    if err != nil {
        return "", err
    }
    return digest.Hash, nil
}
```

## Kein Streaming-Upload auf der nativen CAS-Oberfläche

`Client` hat genau drei native CAS-Methoden — `Put`, `Get`, `Stat` — und
`Put` nimmt ein `[]byte`, kein `io.Reader`; es gibt auf dieser Oberfläche
kein `PutStream` und keine Chunk-Größen-Option. Für eine Datei, die
nicht vollständig in den Speicher passt, verwenden Sie
`Client.ByteStream().Write`, das gegen die REAPI-v2-Oberfläche aus einem
`io.Reader` streamt, oder lesen Sie die Datei in eigenen Chunks und
setzen den Upload selbst zusammen.

## Idempotenz

Der native CAS ist content-addressed: Zwei `Put`-Aufrufe mit identischen
Bytes lösen zum selben Digest auf, sodass ein doppelter Upload nicht als
separater Speicher abgerechnet wird.

## Context-Durchreichung

Der `context.Context`-Parameter von `Put` wird bis zur zugrunde liegenden
HTTP-Anfrage durchgereicht (`Client.do` baut die Anfrage mit
`http.NewRequestWithContext(ctx, ...)`), sodass ein abgebrochener oder
abgelaufener Context einen laufenden `Put` abbricht.

## Fehler

`Client`-Methoden liefern typisierte Fehler, die Sie mit `errors.As`
abgleichen können, keine reinen Nachrichten-Strings:

| Fehlertyp | Ursache | Maßnahme |
|---|---|---|
| `*corelink.AuthError` | Der PAT wurde abgelehnt, fehlte, oder sein Tenant stimmte nicht mit dem Tenant der Anfrage überein | Bestätigen Sie PAT/Tenant zuerst mit einem `Stat`-Aufruf; schlägt auch das fehl, siehe [Troubleshooting](./07-troubleshooting.mdx) |
| `*corelink.QuotaError` | Das Byte- oder Request-Kontingent des Tenants ist ausgeschöpft | Plan-Limits vor einem erneuten Versuch prüfen |
| `*corelink.DigestMismatchError` | Die hochgeladenen Bytes hashten zu einem anderen Digest als vom Server berechnet | Lokal neu berechnen; nicht blind mit denselben Bytes erneut versuchen |

```go
digest, err := cli.Put(ctx, data)
if err != nil {
    var authErr *corelink.AuthError
    var quotaErr *corelink.QuotaError
    switch {
    case errors.As(err, &authErr):
        log.Fatalf("auth error (%d): %s", authErr.StatusCode, authErr.Message)
    case errors.As(err, &quotaErr):
        log.Fatalf("quota exceeded (%d): %s", quotaErr.StatusCode, quotaErr.Message)
    default:
        log.Fatalf("put failed: %v", err)
    }
}
```
