# Action Cache

## Wann diese Anleitung verwenden

Sie wollen das Ergebnis einer Build-Aktion — Exit-Code, stdout,
Output-Dateien — anhand eines Action-Digests cachen und vor einer
erneuten Ausführung nachschlagen.

## `Client.ActionCache()`

`corelink.Client` exponiert den REAPI-v2-Action-Cache über
`Client.ActionCache()`, das einen `*corelink.ActionCacheClient` mit zwei
Methoden zurückgibt:

```go
ac := client.ActionCache()

// Update stores an ActionResult for an action digest.
err := ac.Update(ctx, actionDigest, corelink.ActionResult{
    ExitCode: 0,
    OutputFiles: []corelink.OutputFile{
        {Path: "bin/app", Digest: outputDigest, IsExecutable: true},
    },
})

// Get returns a cached ActionResult, or corelink.ErrActionCacheMiss.
result, err := ac.Get(ctx, actionDigest)
```

`Update` schreibt nach `PUT /bazel/v2/{instance}/blobs/ac/{hash}/{size}`;
`Get` liest vom selben Pfad. Beide operieren gegen `Config.Instance` —
setzen Sie ihn auf der `Config`, die Sie beim Konstruieren des Clients an
`NewClient` übergeben, genauso wie Sie einen Bazel-Remote-Cache-Instanznamen
konfigurieren würden.

## Umgang mit einem Cache-Miss

Ein Miss ist kein Fehler, den Sie per String-Vergleich verzweigen. Gleichen
Sie das Sentinel mit `errors.Is` ab:

```go
result, err := ac.Get(ctx, actionDigest)
switch {
case errors.Is(err, corelink.ErrActionCacheMiss):
    result, err = runActionAndStore(ctx, ac, actionDigest)
    if err != nil {
        return err
    }
case err != nil:
    return fmt.Errorf("action cache lookup: %w", err)
}
```

## Kodierung

Der Server speichert die Action-Cache-Nutzlast als opakes Byte-Blob — er
parst es nicht. `ActionCacheClient.Update` und `.Get` besitzen die
Kodierung selbst (ein privates JSON-Format), sodass `ActionResult` durch
dieses SDK durchgereicht wird, ohne dass Sie Serialisierungscode
schreiben müssen. Eine von einem anderen Client geschriebene Nutzlast
(dem JS/TS-SDK oder einem rohen HTTP-Aufruf) verwendet ihre eigene
Kodierung und lässt sich hier nicht als `ActionResult` dekodieren.
