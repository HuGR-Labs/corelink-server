# Action-Cache-Abfrage und -Speicherung

## Wann Sie diese Anleitung verwenden

Sie umschließen einen JS-gesteuerten Test-Runner (zum Beispiel Jest, Vitest, Playwright) mit einer
Build-Cache-Schicht und möchten Treffer-/Fehltreffer-Semantik, die über einen Action-Digest indiziert wird.

Wenn Sie nur das reine CAS benötigen, siehe
[02-upload-blob](./02-upload-blob.mdx) und
[03-download-blob](./03-download-blob.mdx).

## Die AC-Nutzlast besteht aus opaken Bytes

CoreLink speichert eine **opake `ActionResult`-Byte-Nutzlast**, indiziert über einen Action-Digest
aus 64 Hexadezimalzeichen (`routes/ac.rs`). Das SDK überträgt diese Bytes wortgetreu — Sie besitzen
die Kodierung (zum Beispiel eine serialisierte REAPI-`ActionResult`-Nachricht oder Ihr eigenes
JSON-Manifest, das CAS-Blobs per Digest referenziert). `actionCache.get` gibt ein
`Uint8Array` zurück; `actionCache.put` nimmt eines entgegen.

## Abfrage

```typescript
import { ActionCacheMiss } from "@corelink/client";

async function getOrRun(actionDigest: string): Promise<Uint8Array> {
  try {
    const resultBytes = await client.actionCache.get(actionDigest);
    const manifest = JSON.parse(new TextDecoder().decode(resultBytes));
    return client.get(manifest.stdoutDigest); // fetch the referenced CAS blob
  } catch (e) {
    if (e instanceof ActionCacheMiss) {
      return runLocallyAndStore(actionDigest);
    }
    throw e;
  }
}
```

## Speicherung

```typescript
async function storeResult(
  actionDigest: string,
  stdout: Uint8Array,
  exitCode: number,
): Promise<void> {
  const stdoutDigest = await client.put(stdout);
  const manifest = { stdoutDigest, exitCode };
  const bytes = new TextEncoder().encode(JSON.stringify(manifest));
  await client.actionCache.put(actionDigest, bytes);
}
```

## Unveränderlichkeit & Schutz vor Cache-Poisoning

AC-Einträge sind inhaltlich unveränderlich: Der Server lehnt ein abweichendes Überschreiben eines
bestehenden `(tenant, action_digest)` mit `409` ab, das als `ConflictError` sichtbar wird. Ein
byte-identisches erneutes Speichern ist eine idempotente No-Op.
