# Stapelverarbeitung

## Wann Sie diese Anleitung verwenden

Sie haben viele Blobs zu senden oder abzurufen und möchten die verfügbare Bandbreite
ausschöpfen, ohne das serverseitige Limit pro PAT (256 gleichzeitig) zu überschreiten.

## Muster: Begrenztes `Promise.all`

```typescript
import pLimit from "p-limit";
import { readFile } from "node:fs/promises";

async function uploadMany(
  paths: string[],
  concurrency = 32,
): Promise<string[]> {
  const limit = pLimit(concurrency);
  return Promise.all(
    paths.map((p) =>
      limit(async () => {
        const data = await readFile(p);
        return client.put(data);
      }),
    ),
  );
}
```

## Umgang mit dem Rate-Limit

`RateLimitError` (429) und 503 werden automatisch mit exponentiellem Backoff +
Jitter erneut versucht (standardmäßig 3 Versuche, jeder Backoff auf `maxDelayMs` begrenzt). Anpassen:

```typescript
const client = new CoreLinkClient({
  tenantId: "acme-corp",
  retry: { maxAttempts: 5, baseDelayMs: 200, maxDelayMs: 10_000 },
});
```

Wenn die Versuche erschöpft sind, arbeiten Sie die ausstehenden Aufgaben ab und senden Sie nichts mehr.

## Muster: Digest-indizierte Deduplizierung

```typescript
import { blake3Hex } from "@corelink/client";

async function uploadDedup(
  paths: string[],
): Promise<Record<string, string>> {
  const seen: Record<string, string> = {};
  for (const p of paths) {
    const data = await readFile(p);
    const hex = blake3Hex(data); // same digest the server addresses the blob by
    if (hex in seen) continue;
    seen[hex] = await client.put(data, { expectedDigest: hex });
  }
  return seen;
}
```

Reduziert die Upload-Anzahl bei typischen Build-Ausgaben um 60-90%.
