# Go — `Capabilities.GetCapabilities` ist nicht verfügbar

`Client.Capabilities` existiert auf der Typ-Oberfläche des SDK, aber es
gibt keinen Server-Endpoint dahinter. Die REAPI-v2-Routentabelle
(`crates/corelink-container/src/routes/bazel_v2.rs`) montiert genau fünf
Routen — CAS-Lesen, CAS-Schreiben, AC-Lesen, AC-Schreiben und
`findMissingBlobs` — und keine davon ist eine Capabilities-Oberfläche.
`Capabilities` macht keinen Netzwerkaufruf; es liefert die
Zero-Value-`ServerCapabilities` und einen Fehler, der dies erklärt.

## Code

```go
package main

import (
    "context"
    "fmt"
    "os"

    corelink "go.corelink.humangr.com/corelink-go"
)

func main() {
    ctx := context.Background()
    client, _ := corelink.NewClient(corelink.Config{
        Endpoint: "https://corelink-api.humangr.com",
        PAT:      os.Getenv("CORELINK_PAT"),
    })
    defer client.Close()

    _, err := client.Capabilities(ctx)
    fmt.Println(err)
}
```

## Erwartete Ausgabe

```text
corelink: no REAPI Capabilities endpoint exists on this server (bazel_v2.rs mounts only CAS read/write, AC read/write, and findMissingBlobs); use Client.Health for a readiness check instead
```

## Was stattdessen verwenden

Verwenden Sie `Client.Health` für eine Readiness-Prüfung (siehe das
[Health · Check-Beispiel](../Health/go-check.mdx)). Um eine
Digest-Funktion ohne Negotiation-Endpoint auszuwählen, siehe
[eine Digest-Funktion wählen](./go-pick-digest.mdx).
