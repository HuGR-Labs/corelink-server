# Quickstart — Anmeldung bis zum ersten Cache-Hit in 10 Minuten

**Ziel:** Anmelden, CLI installieren, Konnektivität mit `corelink doctor` prüfen,
Bazel-Repo konfigurieren und beim zweiten Build Cache-Hits beobachten.
**Gesamtbudget: ≤ 10 Minuten für einen erfahrenen Entwickler.**

Jeder hier gezeigte `corelink`-Unterbefehl — `doctor`, `whoami`, `config`,
`bazel-init` — existiert in der ausgelieferten CLI. Die Remote-Cache-
Konfiguration der `.bazelrc` in Schritt 4 funktioniert bereits heute gegen
den produktiven REAPI-v2-Endpunkt und benötigt überhaupt keine CLI.

:::tip Keine Kreditkarte erforderlich
Ein Starter-Account ist kostenlos bis 10 GB. Der Anmelde-Assistent
provisioniert Ihren Tenant, Ihre Region und ein Starter-PAT serverseitig —
kein Abrechnungsschritt erforderlich.
:::

---

## Voraussetzungen

- **Bazel 7+** installiert und im `PATH`
- Ein Browser für die Anmeldung (Clerk, akzeptiert Google / GitHub / E-Mail)
- macOS, Linux oder Windows (WSL2 empfohlen für Windows)

---

## Schritt 1 — Registrieren <span style={{color:"var(--ifm-color-emphasis-600)"}}>(~1 Min.)</span>

1. Öffnen Sie **[https://humangr.com/corelink](https://humangr.com/corelink)** im Browser.
2. Schließen Sie den 2-Schritt-Anmelde-Assistenten ab (wählen Sie Ihre
   primäre Region — `ord` US-Central ist für die meisten Teams ein sicherer Standard).
3. Der Assistent leitet Sie auf die **`/welcome`**-Seite, wo Ihr Starter-PAT
   **genau einmal** angezeigt wird. Kopieren Sie ihn, bevor Sie den Tab schließen.
   Format: `ct_live_xxx…xxx`

:::warning PAT von /welcome kopieren — er wird nur einmal angezeigt
Falls Sie den Tab ohne Kopieren schließen, regenerieren Sie über
**Settings → Access tokens → Regenerate**. Fügen Sie niemals einen echten
PAT in geteilte Dokumente, Slack oder Quellcode ein.
:::

---

## Schritt 2 — CLI installieren <span style={{color:"var(--ifm-color-emphasis-600)"}}>(~1 Min.)</span>

Führen Sie das Installations-Skript aus. Übergeben Sie den in Schritt 1
kopierten PAT und Ihre gewählte Region.

```bash
curl -fsSL https://corelink-get.humangr.com | sh -s -- \
  --token=ct_live_xxx…xxx \
  --region=ord
```

Das Skript:
1. Erkennt Ihre Plattform anhand von `uname -s` / `uname -m` (macOS und
   Linux; `arm64`/`amd64` werden auf `aarch64`/`x86_64` normalisiert, eine
   unbekannte Architektur wird ausdrücklich abgelehnt).
2. Lädt das passende `corelink`-Binary herunter und prüft es gegen die
   neben dem Release-Artefakt veröffentlichte `.sha256`-Datei, **bevor** es
   ausführbar gemacht wird — eine fehlende Prüfsumme bricht die
   Installation ab — und verschiebt es dann nach `/usr/local/bin/corelink`
   (per `sudo`, falls Sie nicht root sind).
3. Schreibt `~/.corelink/config.toml` mit Modus `0600` und Ihrem Token,
   der Region und dem API-Endpunkt.
4. Führt `corelink whoami` aus: das löst Ihre Identität über
   `/v1/users/me` auf und legt die ermittelte `tenant_id` in derselben
   Konfigurationsdatei ab — jeder spätere tenant-bezogene Befehl braucht sie.

`corelink whoami` gibt Ihre `tenant_id`, ein maskiertes `token_prefix` und
die `route_kind` aus. Wenn es durchläuft, weiter zu Schritt 3.

---

## Schritt 3 — `corelink doctor` <span style={{color:"var(--ifm-color-emphasis-600)"}}>(~30 s)</span>

`corelink doctor` führt 8 Konnektivitäts- und Authentifizierungsprüfungen durch:

```bash
corelink doctor
```

Die acht Prüfungen sind, in dieser Reihenfolge, `network`, `auth`,
`storage_write`, `storage_read`, `byok`, `region`, `quota` und
`client_verify`. Jede meldet `ok`, `fail` oder `skip` samt Latenz; eine
fehlgeschlagene Prüfung liefert zusätzlich einen Fehlercode und die nächste
Handlung. Mit `--json` erhalten Sie maschinenlesbare Ausgabe.

Schlägt eine Prüfung fehl, steht der Behebungshinweis in derselben Zeile.
Die häufigsten Fehler sind im Abschnitt
[Fehlerbehebung](#fehlerbehebung) unten aufgeführt.

:::caution `doctor` schreibt in Ihr CAS
Die Prüfung `storage_write` führt ein echtes `PUT` in das CAS Ihres Tenants
aus; `corelink doctor` schlägt daher bei einem berechtigterweise
schreibgeschützten PAT fehl. Wenn Sie nur bestätigen wollen, dass die CLI
authentifiziert ist, nutzen Sie `corelink whoami`.
:::

---

## Schritt 4 — `corelink bazel-init` <span style={{color:"var(--ifm-color-emphasis-600)"}}>(~30 s)</span>

Wechseln Sie in das Stammverzeichnis Ihres Bazel-Repositorys und führen Sie aus:

```bash
cd /pfad/zu/ihrem-bazel-repo
corelink bazel-init
```

`corelink bazel-init` fügt die Remote-Cache-Zeilen zu Ihrer `.bazelrc` hinzu
und schreibt eine `.corelink/credentials`-Datei (Modus `0600`):

```text
corelink bazel-init: appended to .bazelrc:
  build --remote_cache=https://corelink-api.humangr.com/bazel/v2
  build --remote_instance_name=acme-prod
  build --remote_header=Authorization=Bearer ${CORELINK_PAT}
  build --remote_timeout=30s
  build --remote_upload_local_results=true
corelink bazel-init: wrote .corelink/credentials (mode 0600)
```

`bazel-init` ist **idempotent**: ein zweiter Aufruf erkennt die vorhandene
Markierungszeile in `.bazelrc` und beendet sich mit `0` ohne Duplikate.

:::tip Standard-Bazel? Dann den Plain-HTTP-Alias verwenden
Die obigen Zeilen sind das **REAPI-v2-ByteStream**-Schema unter
`/bazel/v2/<tenant>`, das einen REAPI/ByteStream-kompatiblen Client voraussetzt.
Standard-Bazel wird vom Plain-HTTP-Alias bedient, der aktiv ist: Er nimmt die
Pfade `/cas/<sha256>` und `/ac/<sha256>` entgegen, die Bazel sendet, und leitet
den Mandanten aus dem PAT ab (daher kein `--remote_instance_name`):

```ini
build --remote_cache=https://corelink-api.humangr.com/bazel/cache
build --remote_header=Authorization=Bearer ${CORELINK_PAT}
build --remote_upload_local_results=true
```

Details im [Bazel-Integrationsleitfaden](../integrations/bazel).
:::

:::tip .bazelrc committen, nicht .corelink/credentials
Fügen Sie `.bazelrc` zu Git hinzu, damit das Team die Konfiguration teilt.
Fügen Sie `.corelink/credentials` zur `.gitignore` hinzu — die Datei
enthält ein entwicklerspezifisches PAT.
:::

---

## Schritt 5 — Erster Build (kalter Cache) <span style={{color:"var(--ifm-color-emphasis-600)"}}>(~3 Min.)</span>

Führen Sie Ihren Bazel-Build zum ersten Mal aus. Dabei wird der Remote-Cache befüllt.

```bash
bazel build //...
```

Dies ist der **kalte** Lauf, der Ihre Build-Artefakte hochlädt.

---

## Schritt 6 — Zweiter Build (Cache-Hits) <span style={{color:"var(--ifm-color-emphasis-600)"}}>(~1 Min.)</span>

Führen Sie denselben Build erneut aus:

```bash
bazel build //...
```

Diesmal holt Bazel aus dem CoreLink-Cache statt neu zu bauen:

```text
INFO: 42 processes: 38 remote cache hit, 4 internal.
```

Dieser `remote cache hit`-Zähler ist das **Aktivierungsereignis** — Ihr
erster erfolgreicher CoreLink-Cache-Hit.

:::note Warum zweimal bauen?
Der erste Build befüllt den Cache (MISS → UPLOAD). Der zweite liest daraus
(HIT → DOWNLOAD). Dieses Zwei-Lauf-Muster ist bewusst — der Cache bringt
den größten Nutzen beim zweiten Lauf Ihrer CI-Pipeline.
:::

## Fehlerbehebung {#fehlerbehebung}

### Regions-Fehlanpassung — hohe Latenz oder `UNAVAILABLE` gRPC-Fehler

**Symptom:** die Prüfung `network` in `corelink doctor` meldet eine Latenz
über 200 ms, oder Bazel meldet `UNAVAILABLE`.

**Lösung:**
```bash
corelink config set defaults.region <korrekte-region>
corelink bazel-init --force
```

Verfügbare Regionen: `ord` (US-Central), `iad` (US-East), `lhr` (EU-West),
`nrt` (AP-Northeast), `syd` (AP-Southeast).

### Token nicht gesetzt — `UNAUTHENTICATED` bei jeder Bazel-Aktion

**Symptom:** Bazel meldet `UNAUTHENTICATED`.

**Lösung:** Prüfen Sie `echo $CORELINK_PAT` oder setzen Sie es via config:

```bash
corelink config set auth.pat "ct_live_xxx…xxx"
```

### `.bazelrc`-Duplikat-Warnung

**Symptom:** `WARNING: Duplicate rc option: --remote_cache`.

**Lösung:** Entfernen Sie doppelte Zeilen manuell und prüfen Sie mit `corelink doctor`.

### Die Prüfung `storage_write` in `corelink doctor` schlägt fehl

**Symptom:** die Prüfung `storage_write` meldet `fail` (der Test-Blob wurde
beim Upload abgelehnt).

**Lösung:** Prüfen Sie die Tenant-ID und regenerieren Sie das PAT mit `write`-Scope:

```bash
corelink config set defaults.tenant_id <ihre-tenant-id>
```
