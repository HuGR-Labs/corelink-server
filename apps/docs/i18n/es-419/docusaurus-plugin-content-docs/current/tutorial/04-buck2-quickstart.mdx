# Buck2 remote cache

:::warning Buck2 is not yet supported
CoreLink is a **cache-only** platform served over **HTTP**. Buck2's remote
cache and remote-execution client connects over **gRPC**
(`buck2_re_client` with `engine_address` / `cas_address` / `action_cache_address`),
and CoreLink does **not** expose a gRPC remote-execution endpoint. There is no
working Buck2 configuration today, so this page does not provide one — a config
pointed at a `grpcs://` CoreLink address would simply fail to connect.
:::

## What works today

In the Bazel family, **Bazel itself is fully served over plain HTTP** — two live
surfaces: the stock-Bazel HTTP alias at `/bazel/cache` (`/cas/<sha256>` and
`/ac/<sha256>`, what vanilla `--remote_cache` emits) and the **REAPI v2
ByteStream** scheme at `/bazel/v2/<tenant>`. If you can use Bazel, see the
[Bazel quickstart](./03-bazel-quickstart). Buck2 cannot use either: it has no
plain-HTTP cache backend, so `/bazel/cache` is unreachable for it, and
`/bazel/v2` is REST — not the gRPC REAPI service `buck2_re_client` dials.

For any tool that speaks plain HTTP, the [raw HTTP (curl)](../integrations/raw-curl)
and native CAS endpoints are available directly.

## Want Buck2?

Buck2 support is not on the current cache surface. If you need it, let us know
via [support](../troubleshooting) so we can weigh it against the roadmap.
