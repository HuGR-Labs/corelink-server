# Go — `Capabilities.GetCapabilities` no existe en el servidor

`Client.Capabilities` existe en la superficie de tipos del SDK, pero no
hay ningún endpoint de servidor detrás de él. La tabla de rutas de REAPI
v2 (`crates/corelink-container/src/routes/bazel_v2.rs`) expone
exactamente cinco rutas — lectura de CAS, escritura de CAS, lectura de
AC, escritura de AC y `findMissingBlobs` — y ninguna es una superficie
de capabilities. `Capabilities` no hace ninguna llamada de red; devuelve
el `ServerCapabilities` en su valor cero junto con un error que explica
el motivo.

## Código

```go
package main

import (
    "context"
    "fmt"
    "os"

    corelink "go.corelink.humangr.com/corelink-go"
)

func main() {
    ctx := context.Background()
    client, _ := corelink.NewClient(corelink.Config{
        Endpoint: "https://corelink-api.humangr.com",
        PAT:      os.Getenv("CORELINK_PAT"),
    })
    defer client.Close()

    _, err := client.Capabilities(ctx)
    fmt.Println(err)
}
```

## Salida esperada

```text
corelink: no REAPI Capabilities endpoint exists on this server (bazel_v2.rs mounts only CAS read/write, AC read/write, and findMissingBlobs); use Client.Health for a readiness check instead
```

## Qué usar en su lugar

Use `Client.Health` para una verificación de disponibilidad (vea el
[ejemplo Health · Check](../Health/go-check.mdx)). Para elegir una
función de digest sin un endpoint de negociación, vea
[elegir una función de digest](./go-pick-digest.mdx).
