# REAPI v2 reference

CoreLink implementa un subconjunto compatible a nivel de wire, con
alcance por tenant, de [`bazelbuild/remote-apis @ v2.12.0`](https://github.com/bazelbuild/remote-apis/tree/v2.12.0). Bazel 6+, y cualquier otro cliente REAPI v2 que hable **HTTP/REST**, se conectan **sin cambios de código** — solo difieren el endpoint de la caché y el PAT. CoreLink no expone ingress gRPC, por lo que los clientes REAPI que solo hablan gRPC (Buck2, Pants, NativeLink) no pueden conectarse.

## Authentication

Cada RPC lleva un PAT en el encabezado de metadatos `Authorization: Bearer <pat>`. El formato canónico del token es:

```
corelink_<env>_<token_id>.<random_secret>.<hmac_sig>
```

El placeholder usado en todo este sitio — `corelink_dev_t_xxx.xxx.xxx` — es intencional y nunca debe aparecer en producción.

## Auto-generated service pages

Las páginas bajo esta sección se regeneran a partir de los archivos `.proto` vendorizados mediante `pnpm docs:gen`. CI verifica cero desviación entre el proto y el MDX renderizado (`pnpm docs:gen:check`) en cada PR.

Explore el índice generado para todos los servicios en el build actual.

## Manual code examples

Para cada servicio, hay ejemplos escritos a mano en cuatro lenguajes bajo `_examples/<Service>/`:

- **Python** (`corelink-py`)
- **Go** (`corelink-go`)
- **Node / TypeScript** (`@corelink/client`)
- **CLI** (`corelink`)

Los ejemplos cubren los flujos más comunes: autenticación por PAT, `BatchUpdateBlobs`, `BatchReadBlobs`, `FindMissingBlobs`, `Capabilities.GetCapabilities`, `ByteStream.Read`, `ByteStream.Write`, y sondeo de salud.

## Error model

CoreLink mapea cada código de estado de REAPI v2 a un identificador `error_taxonomy` estable (`COR_CAS_*`, `COR_AUTH_*`, `COR_QUOTA_*`). Vea [error taxonomy](../../tutorial/06-verify-cache-hit.mdx#troubleshooting) para los casos más comunes.
