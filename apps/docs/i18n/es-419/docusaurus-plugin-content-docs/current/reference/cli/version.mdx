# `corelink version`

Print the package version and the build metadata compiled into the binary.
The current release workflow injects `SOURCE_DATE_EPOCH` only: it does not
inject `GIT_COMMIT_SHA` or `TARGET`. Consequently, `git_rev` is `unknown`,
`build_timestamp` is an `epoch:` value in release builds (or `unknown` in a
local build), and `target_triple` falls back to the target architecture (for
example, `x86_64`).

## Synopsis

```bash
corelink version [--output <FORMAT>]
```

## Flags

| Flag | Required | Default | Description |
|---|---|---|---|
| `--output` | no | `text` | `text` or `json`. |

## Examples

```bash
corelink version
```

```text
corelink 0.1.0
  git rev:      unknown
  built:        unknown
  target:       x86_64
```

```bash
corelink version --output json
```

```json
{
  "version": "0.1.0",
  "git_rev": "unknown",
  "build_timestamp": "unknown",
  "target_triple": "x86_64"
}
```

## Notes

- This subcommand does **not** require a PAT.
- `GIT_COMMIT_SHA` and `TARGET` are optional build-time injections, not
  release guarantees. Do not interpret `unknown` or the architecture fallback
  as a verified source revision or a target triple.
- Attestation fields are intentionally absent while no published, independently
  retrievable bundle exists. Consumers must accept their absence and must not
  derive an artifact URL from `version` or `git_rev`. A future published bundle
  may add an optional field with its exact URL.

## Exit codes

`0` success.
