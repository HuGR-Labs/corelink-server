# `POST` `/v1/dpa/accept`

> Record click-through acceptance of the current DPA version.

- **Operation ID:** `dpaAccept`
- **Tag:** `dpa`
- **Rate-limit class:** default (600 req/min/PAT)

## Description

Records 6-field consent proof (`notice_text_hash`, `notice_version`,
`locale`, `wording_id`, `ui_capture_ts`, `submission_ts` server-set)
and emits an RS256-signed JWT receipt. Idempotent on
`(tenant_id, notice_text_hash, ui_capture_ts)`.

## Authentication

- `BearerPAT`
- `ClerkSessionCookie`

## Parameters

_None._

## Request body

- **Media type:** `application/json`
- **Required:** yes
- **Schema:** [`DpaAcceptanceRequest`](#schema-dpaacceptancerequest)

## Responses

| Status | Schema | Description |
| --- | --- | --- |
| `201` | [`DpaAcceptanceReceipt`](#schema-dpaacceptancereceipt) | Acceptance recorded; JWT receipt returned and emailed. |
| `401` | [`ErrorEnvelope`](#schema-errorenvelope) | Missing or invalid credentials. |
| `409` | [`DpaAcceptanceReceipt`](#schema-dpaacceptancereceipt) | Idempotent replay — original receipt returned unchanged. |
| `422` | [`ErrorEnvelope`](#schema-errorenvelope) | Schema-valid but semantically invalid payload. |
| `429` | [`ErrorEnvelope`](#schema-errorenvelope) | Rate-limit exceeded. |
| `500` | [`ErrorEnvelope`](#schema-errorenvelope) | Server error. Safe to retry idempotent operations. |
