# Action Cache

## When to use this guide

Quiere almacenar en caché el resultado de una acción de build — código
de salida, stdout, archivos de salida — indexado por un digest de
acción, y buscarlo antes de volver a ejecutar la acción.

## `Client.ActionCache()`

`corelink.Client` expone el Action Cache de REAPI v2 mediante
`Client.ActionCache()`, que devuelve un `*corelink.ActionCacheClient`
con dos métodos:

```go
ac := client.ActionCache()

// Update stores an ActionResult for an action digest.
err := ac.Update(ctx, actionDigest, corelink.ActionResult{
    ExitCode: 0,
    OutputFiles: []corelink.OutputFile{
        {Path: "bin/app", Digest: outputDigest, IsExecutable: true},
    },
})

// Get returns a cached ActionResult, or corelink.ErrActionCacheMiss.
result, err := ac.Get(ctx, actionDigest)
```

`Update` escribe en `PUT /bazel/v2/{instance}/blobs/ac/{hash}/{size}`;
`Get` lee de la misma ruta. Ambos operan contra `Config.Instance` —
configúrelo en el `Config` que pasa a `NewClient` al construir el
cliente, del mismo modo en que configuraría un nombre de instancia de
remote cache de Bazel.

## Handling a cache miss

Un miss no es un error que se distingue por cadena. Compárelo con el
centinela usando `errors.Is`:

```go
result, err := ac.Get(ctx, actionDigest)
switch {
case errors.Is(err, corelink.ErrActionCacheMiss):
    result, err = runActionAndStore(ctx, ac, actionDigest)
    if err != nil {
        return err
    }
case err != nil:
    return fmt.Errorf("action cache lookup: %w", err)
}
```

## Encoding

El servidor almacena el payload del Action Cache como un blob de
bytes opaco — no lo interpreta. `ActionCacheClient.Update` y `.Get`
son dueños de la codificación en sí (una forma JSON privada), así que
`ActionResult` viaja de ida y vuelta a través de este SDK sin que usted
escriba ningún código de serialización. Un payload escrito por un
cliente distinto (el SDK de JS/TS, o una llamada HTTP directa) usa su
propia codificación y no se decodificará como un `ActionResult` aquí.
