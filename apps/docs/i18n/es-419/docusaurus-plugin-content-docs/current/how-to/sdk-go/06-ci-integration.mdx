# CI integration

## When to use this guide

Your build is a Go project (or its smoke tests are written in Go) and you
want CoreLink as a shared cache without shelling out to the CLI.

## GitHub Actions

```yaml
# .github/workflows/build.yml
jobs:
  build:
    runs-on: ubuntu-latest
    env:
      CORELINK_PAT: ${{ secrets.CORELINK_PAT }}
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-go@v5
        with:
          go-version: "1.22"
      - run: cargo build --release -p corelink-go   # builds libcorelink_go for the cgo link
      - run: CGO_LDFLAGS="-L./target/release -lcorelink_go" go run ./ci/warm-cache
```

```go
// ci/warm-cache/main.go
package main

import (
    "context"
    "log"
    "os"

    "github.com/HumanGuardrail/corelink-go/v1"
)

func main() {
    ctx := context.Background()
    cli, err := corelink.NewClient(corelink.Config{
        PAT:      os.Getenv("CORELINK_PAT"),
        TenantID: os.Getenv("CORELINK_TENANT"),
    })
    if err != nil {
        log.Fatal(err)
    }
    defer cli.Close()

    // There is no Bench method on this SDK — warm the cache with a real
    // Put/Get round trip instead, and fail the job on error.
    digest, err := cli.Put(ctx, []byte("ci-warm-cache-probe"))
    if err != nil {
        log.Fatalf("cache warm-up failed: %v", err)
    }
    if _, err := cli.Get(ctx, digest); err != nil {
        log.Fatalf("cache verify failed: %v", err)
    }
    log.Println("cache reachable")
}
```

## GitLab CI

```yaml
build:
  image: golang:1.22
  variables:
    CORELINK_PAT: $CORELINK_PAT  # masked
  script:
    - cargo build --release -p corelink-go
    - CGO_LDFLAGS="-L./target/release -lcorelink_go" go run ./ci/warm-cache
```

## CircleCI

```yaml
version: 2.1
jobs:
  build:
    docker:
      - image: cimg/go:1.22
    environment:
      CORELINK_PAT: $CORELINK_PAT
    steps:
      - checkout
      - run: cargo build --release -p corelink-go
      - run: CGO_LDFLAGS="-L./target/release -lcorelink_go" go run ./ci/warm-cache
```

## Job-scoped PATs

There is no self-service API to mint a short-lived PAT per pipeline today
(see [Security model](../../security.md)) — email
[support@humangr.com](mailto:support@humangr.com) to request a dedicated CI
PAT, then inject it via your CI provider's secret store as shown above.
