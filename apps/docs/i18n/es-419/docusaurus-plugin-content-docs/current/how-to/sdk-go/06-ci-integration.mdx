# CI integration

## When to use this guide

Su build es un proyecto Go (o sus smoke tests están escritos en Go) y
quiere usar CoreLink como caché compartida sin invocar la CLI.

## GitHub Actions

```yaml
# .github/workflows/build.yml
jobs:
  build:
    runs-on: ubuntu-latest
    env:
      CORELINK_PAT: ${{ secrets.CORELINK_PAT }}
      GOPROXY: https://humangr.com/corelink/docs/goproxy,https://proxy.golang.org,direct
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-go@v5
        with:
          go-version: "1.22"
      - run: go get go.corelink.humangr.com/corelink-go@v0.1.0  # GOPROXY set above
      - run: go run ./ci/warm-cache
```

```go
// ci/warm-cache/main.go
package main

import (
    "context"
    "log"
    "os"

    "go.corelink.humangr.com/corelink-go"
)

func main() {
    ctx := context.Background()
    cli, err := corelink.NewClient(corelink.Config{
        Endpoint: "https://corelink-api.humangr.com",
        PAT:      os.Getenv("CORELINK_PAT"),
        TenantID: os.Getenv("CORELINK_TENANT"),
    })
    if err != nil {
        log.Fatal(err)
    }
    defer cli.Close()

    // Warm the cache with a real Put/Get round trip and fail the job on error.
    digest, err := cli.Put(ctx, []byte("ci-warm-cache-probe"))
    if err != nil {
        log.Fatalf("cache warm-up failed: %v", err)
    }
    if _, err := cli.Get(ctx, digest); err != nil {
        log.Fatalf("cache verify failed: %v", err)
    }
    log.Println("cache reachable")
}
```

## GitLab CI

```yaml
build:
  image: golang:1.22
  variables:
    CORELINK_PAT: $CORELINK_PAT  # masked
    GOPROXY: "https://humangr.com/corelink/docs/goproxy,https://proxy.golang.org,direct"
  script:
    - go get go.corelink.humangr.com/corelink-go@v0.1.0  # GOPROXY set above
    - go run ./ci/warm-cache
```

## CircleCI

```yaml
version: 2.1
jobs:
  build:
    docker:
      - image: cimg/go:1.22
    environment:
      CORELINK_PAT: $CORELINK_PAT
      GOPROXY: https://humangr.com/corelink/docs/goproxy,https://proxy.golang.org,direct
    steps:
      - checkout
      - run: go get go.corelink.humangr.com/corelink-go@v0.1.0  # GOPROXY set above
      - run: go run ./ci/warm-cache
```

## Job-scoped PATs

Emita usted mismo un PAT de CI dedicado — desde la página **Keys** del panel
o con `POST /v1/customer/keys` y el cuerpo `{"name": "...", "scopes": [ … ]}`
(vea [Security model](../../security.md)) — y luego inyéctelo mediante el
almacén de secretos de su proveedor de CI como se muestra arriba. Para
revocarlo, use `POST /v1/customer/keys/{pat_id}/revoke`.

El cuerpo de creación acepta solo `{name, scopes}`: no hay campo de TTL, así que
un PAT no vence por sí solo — un token por pipeline significa emitir-y-revocar,
no un token con vencimiento. Emitir un PAT con scope de escritura también exige
que quien llama ya tenga una capacidad de escritura en el caché; un token de
solo lectura (`cas:r`) recibe `403`.
