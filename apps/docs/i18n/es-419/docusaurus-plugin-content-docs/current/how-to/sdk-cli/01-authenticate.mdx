# Autenticar la CLI

## Cuándo usar esta guía

Usted instaló el binario `corelink` (un único ejecutable firmado para macOS,
Linux y Windows) y necesita ejecutar cualquier comando, excepto `version`.

## Requisitos previos

- Binario `corelink` en el `$PATH`. Instálelo mediante su gestor de paquetes o
  descárguelo desde la página de releases de GitHub. Verifique la atestación SLSA
  antes del primer uso.
- Un PAT generado en `https://corelink-app.humangr.com/tokens`.

## Recomendado: variable de entorno

```bash
export CORELINK_PAT="corelink_dev_t_xxx.xxx.xxx"
corelink ls --tenant acme-corp
```

## Alternativa: archivo de configuración

```bash
corelink config set auth.pat corelink_dev_t_xxx.xxx.xxx
corelink config set defaults.tenant_id acme-corp
```

El archivo se encuentra en `~/.corelink/config.toml` en macOS/Linux y en
`%APPDATA%\corelink\config.toml` en Windows. El modo del archivo se impone como
`0600` y el PAT se oculta con `corelink config list`.

## Prohibido: PAT como bandera de la CLI

```bash
# DO NOT DO THIS — the CLI exits 2 with an explicit security error.
corelink --pat=corelink_dev_t_xxx.xxx.xxx ls --tenant acme-corp
```

CTRL-CRED-001 prohíbe la bandera `--pat` porque los argumentos de proceso se filtran
mediante `ps`, el historial del shell y los logs de CI. La CLI rechaza la bandera
antes de cualquier otro análisis.

## Verificar

```bash
corelink doctor --json | jq '.checks[] | select(.name=="auth")'
```

Se espera `status: "ok"`. Cualquier otro estado se asigna a un código
`COR_AUTH_*` con un enlace directo al documento de la siguiente acción correcta.
