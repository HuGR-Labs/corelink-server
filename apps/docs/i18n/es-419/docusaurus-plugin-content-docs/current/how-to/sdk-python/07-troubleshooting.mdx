# Troubleshooting

## When to use this guide

A call raised an exception and you need the fix. `corelink-py` has no
`doctor()` or `whoami()` method and no `COR_*` error-code strings — every
SDK error is one of the six concrete subclasses of `corelink.CoreLinkError`
below, distinguished by **type**, not by a code field.

If you want the 8-check `doctor` diagnostic, use the
[`corelink` CLI](../../reference/cli/doctor.mdx) instead —
`corelink doctor --json`.

## The exception taxonomy

All inherit `corelink.exceptions.CoreLinkError` (catch this as the
single base type if you don't need to distinguish):

| Exception | Raised when | First action |
|---|---|---|
| `CoreLinkAuthError` | Server returned `401` (missing/invalid/revoked PAT) | Re-export `CORELINK_PAT`; if it's set, the PAT itself is invalid — mint a new one. |
| `CoreLinkNotFoundError` | Server returned `404` (never uploaded) or `410` (erased) | Confirm the tenant and digest with `corelink stat <digest>`. |
| `CoreLinkDigestMismatchError` | `422` from a `put`/`put_stream` with a wrong `expected_digest`, **or** a client-side BLAKE3 mismatch on `get` (has `.expected`/`.actual` attributes when known) | Server-side: drop `expected_digest`, let the SDK compute it. Client-side: possible corruption in transit — retry; persistent → open a support ticket. |
| `CoreLinkQuotaError` | Server returned `402` (tenant over storage/spend ceiling; has `.status_code`) | Check usage with `corelink stat`; raise the plan limit or evict old digests. |
| `CoreLinkRequestError` | Any other `4xx` (has `.status_code` and, when the response body carried one, `.error_code`) | Read `.error_code`/message; usually a malformed request. |
| `CoreLinkServerError` | `5xx` (has `.status_code`) | Transient — retry with backoff; persistent → open a support ticket. |

**Network-level failures** (DNS, connection refused, timeout) are **not**
wrapped — they surface as the underlying `httpx` exceptions
(`httpx.ConnectError`, `httpx.TimeoutException`, ...), raised before the
SDK gets a chance to inspect a response.

## When the SDK hangs or leaks connections

Forgetting the context manager leaks the underlying `httpx` connection
pool. Use whichever client matches your code — `with` for the sync
`CoreLinkClient`, `async with` for `AsyncCoreLinkClient` (they are not
interchangeable, see [Authenticate](./01-authenticate.mdx)):

```python
# WRONG — leaks the pool, and awaiting a sync method is also an error
client = CoreLinkClient(tenant_id="acme-corp")
await client.get(digest)

# RIGHT (async)
async with AsyncCoreLinkClient(tenant_id="acme-corp") as client:
    data = await client.get(digest)

# RIGHT (sync)
with CoreLinkClient(tenant_id="acme-corp") as client:
    data = client.get(digest)
```

## Filing a bug

Include the exception type and message (`repr(e)`), the `corelink-py`
version (`python -c "import corelink; print(corelink.__version__)"` if
exposed, otherwise `pip show corelink-py`), and whether you're on the
sync or async client. Never include your PAT.
