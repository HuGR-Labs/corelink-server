# Operaciones por lotes

## Cuándo usar esta guía

Usted tiene muchos blobs para enviar o descargar y quiere saturar el ancho de banda
disponible sin exceder el límite por PAT del lado del servidor (256 concurrentes).

## Patrón: `Promise.all` acotado

```typescript
import pLimit from "p-limit";
import { readFile } from "node:fs/promises";

async function uploadMany(
  paths: string[],
  concurrency = 32,
): Promise<string[]> {
  const limit = pLimit(concurrency);
  return Promise.all(
    paths.map((p) =>
      limit(async () => {
        const data = await readFile(p);
        return client.put(data);
      }),
    ),
  );
}
```

## Manejo del límite de tasa

`RateLimitError` (429) y 503 se reintentan automáticamente con retroceso exponencial +
jitter (3 intentos de forma predeterminada, cada retroceso limitado a `maxDelayMs`). Personalice:

```typescript
const client = new CoreLinkClient({
  tenantId: "acme-corp",
  retry: { maxAttempts: 5, baseDelayMs: 200, maxDelayMs: 10_000 },
});
```

Cuando se agotan los intentos, drene el trabajo pendiente y deje de enviar.

## Patrón: deduplicación indexada por digest

```typescript
import { blake3Hex } from "@corelink/client";

async function uploadDedup(
  paths: string[],
): Promise<Record<string, string>> {
  const seen: Record<string, string> = {};
  for (const p of paths) {
    const data = await readFile(p);
    const hex = blake3Hex(data); // same digest the server addresses the blob by
    if (hex in seen) continue;
    seen[hex] = await client.put(data, { expectedDigest: hex });
  }
  return seen;
}
```

Reduce la cantidad de subidas en un 60-90% en salidas de compilación típicas.
