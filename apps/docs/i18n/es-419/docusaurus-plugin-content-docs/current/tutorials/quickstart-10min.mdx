# Quickstart — registro hasta el primer cache hit en 10 minutos

**Objetivo:** registrarte, instalar el CLI, verificar la conectividad con
`corelink doctor`, configurar tu repositorio Bazel y ver cache HITs en el
segundo build.
**Presupuesto total: ≤ 10 minutos para un ingeniero con experiencia.**

Todos los comandos son canónicos y verificados contra el MVP de `corelink-cli`
(commit [`71d7f6a9`](https://github.com/humangr-labs/corelink-cli/commit/71d7f6a9),
subcomandos: `ping`, `bazel-init`; `doctor` llega en la próxima release del CLI —
la documentación refleja el UX planificado antes del binario).

:::tip Sin tarjeta de crédito
Una cuenta inicial es gratuita hasta 10 GB. El asistente de registro
provisiona tu tenant, región y un PAT inicial en el servidor — sin paso de
facturación.
:::

---

## Antes de empezar

- **Bazel 7+** instalado y en el `PATH`
- Un navegador para el registro (Clerk, acepta Google / GitHub / correo)
- macOS, Linux o Windows (WSL2 recomendado para Windows)

---

## Paso 1 — Regístrate <span style={{color:"var(--ifm-color-emphasis-600)"}}>(~1 min)</span>

1. Abre **[https://corelink-app.humangr.com](https://corelink-app.humangr.com)** en tu navegador.
2. Completa el asistente de registro en 2 pasos (elige tu región primaria — `ord`
   US-Central es un buen valor predeterminado para la mayoría de los equipos).
3. El asistente te lleva a la página **`/welcome`** donde tu PAT inicial se muestra
   **exactamente una vez**. Cópialo antes de cerrar la pestaña.
   Formato: `ct_live_xxx…xxx`

:::warning Copia tu PAT de /welcome — se muestra solo una vez
Si cierras la pestaña sin copiarlo, regeneralo en **Settings → Access tokens → Regenerate**.
Nunca pegues un PAT real en documentos compartidos, Slack o código fuente.
:::

---

## Paso 2 — Instala el CLI <span style={{color:"var(--ifm-color-emphasis-600)"}}>(~1 min)</span>

Ejecuta el script de instalación. Pasa el PAT copiado en el Paso 1 y la región elegida.

```bash
curl -fsSL https://corelink-get.humangr.com | sh -s -- \
  --token=ct_live_xxx…xxx \
  --region=ord
```

El script:
1. Detecta tu plataforma (macOS arm64/amd64, Linux amd64/arm64).
2. Descarga el binario estático `corelink` en `/usr/local/bin`
   (fallback a `~/.local/bin` si `/usr/local/bin` no es escribible).
3. Escribe `~/.config/corelink/config.toml` con tu PAT y tenant ID.
4. Ejecuta `corelink ping` contra la región CAS más cercana e imprime el RTT.

Salida esperada:

```text
corelink-get: detected darwin/arm64
corelink-get: downloading corelink 0.1.0 ...
corelink-get: installed /usr/local/bin/corelink
corelink-get: writing ~/.config/corelink/config.toml
corelink ping: ok (region=cf-ord, rtt=22ms, tenant=acme-prod)
```

Si `corelink ping` imprime `ok`, avanza al Paso 3.

---

## Paso 3 — `corelink doctor` <span style={{color:"var(--ifm-color-emphasis-600)"}}>(~30 s)</span>

`corelink doctor` ejecuta 8 verificaciones de conectividad y autenticación:

```bash
corelink doctor
```

Salida saludable:

```text
[1/8] config file found              ✓  ~/.config/corelink/config.toml
[2/8] PAT format valid               ✓  prefix=ct_live, length=ok
[3/8] PAT not expired                ✓  ttl=365d (tenant=acme-prod)
[4/8] DNS resolution                 ✓  cas.corelink.humangr.com → <IP>
[5/8] TLS handshake                  ✓  TLSv1.3, 0-RTT=off
[6/8] API ping (HTTP/2)              ✓  200 OK (rtt=18ms, region=cf-ord)
[7/8] gRPC channel (REAPI v2)        ✓  capabilities handshake ok
[8/8] tenant write permission        ✓  can upload 1-byte probe blob
8/8 checks PASS
```

Si alguna verificación muestra `✗`, la salida incluye una sugerencia de
corrección. Los fallos más comunes están en la sección
[Solución de problemas](#solucion-de-problemas) abajo.

:::note Nota de release del CLI
`corelink doctor` llega en la próxima release. Si tu binario es anterior,
usa `corelink ping` como sustituto más ligero (verifica solo los puntos 4–6).
:::

---

## Paso 4 — `corelink bazel-init` <span style={{color:"var(--ifm-color-emphasis-600)"}}>(~30 s)</span>

Ve a la raíz de tu repositorio Bazel y ejecuta:

```bash
cd /ruta/a/tu-repo-bazel
corelink bazel-init
```

`corelink bazel-init` agrega las líneas de remote-cache a tu `.bazelrc`
y escribe un archivo `.corelink/credentials` (modo `0600`) con alcance
para la raíz del repositorio:

```text
corelink bazel-init: appended to .bazelrc:
  build --remote_cache=grpcs://cas.corelink.humangr.com:443
  build --remote_header=x-corelink-tenant=acme-prod
  build --remote_header=authorization=Bearer ${CORELINK_PAT}
  build --remote_upload_local_results=true
corelink bazel-init: wrote .corelink/credentials (mode 0600)
```

`bazel-init` es **idempotente**: ejecutarlo una segunda vez detecta la
línea marcadora existente en `.bazelrc` y termina con `0` sin duplicados.

:::tip Comitear .bazelrc, no .corelink/credentials
Agrega `.bazelrc` a git para que el equipo comparta la configuración.
Agrega `.corelink/credentials` al `.gitignore` — el archivo contiene
un PAT por desarrollador.
:::

---

## Paso 5 — Primer build (cache frío) <span style={{color:"var(--ifm-color-emphasis-600)"}}>(~3 min)</span>

Ejecuta tu build Bazel por primera vez. Esto llena el cache remoto.

```bash
bazel build //...
```

Esta es la ejecución **fría** que sube tus artefactos de build.

---

## Paso 6 — Segundo build (cache HITs) <span style={{color:"var(--ifm-color-emphasis-600)"}}>(~1 min)</span>

Ejecuta el mismo build nuevamente:

```bash
bazel build //...
```

Esta vez Bazel obtiene del cache CoreLink en lugar de recompilar:

```text
INFO: 42 processes: 38 remote cache hit, 4 internal.
```

Ese contador `remote cache hit` es el **evento de activación** — tu
primer cache hit CoreLink exitoso.

:::note ¿Por qué compilar dos veces?
El primer build llena el cache (MISS → UPLOAD). El segundo lee de él
(HIT → DOWNLOAD). Este patrón de dos ejecuciones es intencional — el
cache es más valioso en la segunda ejecución de tu pipeline de CI.
:::

## Solución de problemas {#solucion-de-problemas}

### Incompatibilidad de región — alta latencia o errores gRPC `UNAVAILABLE`

**Síntoma:** RTT > 200 ms en `corelink doctor` paso 6, o Bazel registra `UNAVAILABLE`.

**Solución:**
```bash
corelink config set defaults.region <región-correcta>
corelink bazel-init --force
```

Regiones disponibles: `ord` (US-Central), `iad` (US-East), `lhr` (EU-West),
`nrt` (AP-Northeast), `syd` (AP-Southeast).

### Token no configurado — `UNAUTHENTICATED` en cada acción Bazel

**Síntoma:** Bazel registra `UNAUTHENTICATED`.

**Solución:** verifica `echo $CORELINK_PAT` o configúralo via config:

```bash
corelink config set auth.pat "ct_live_xxx…xxx"
```

### Advertencia de línea duplicada en `.bazelrc`

**Síntoma:** `WARNING: Duplicate rc option: --remote_cache`.

**Solución:** elimina las líneas duplicadas manualmente y confirma con `corelink doctor`.

### Verificación 8 de `corelink doctor` falla — `PERMISSION_DENIED`

**Síntoma:** `[8/8] tenant write permission  ✗  PERMISSION_DENIED`.

**Solución:** verifica el tenant ID y regenera el PAT con alcance `write`:

```bash
corelink config set defaults.tenant_id <tu-tenant-id>
```
