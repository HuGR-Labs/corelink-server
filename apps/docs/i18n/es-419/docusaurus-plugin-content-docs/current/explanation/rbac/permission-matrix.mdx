# Permission matrix

The master table: every CoreLink permission against every role.

Legend:

- ✅ granted (single-actor; no approver needed).
- 2P **dual-approval** — granted but the operation routes through
  `POST /v1/admin/ops` with `X-Dual-Approver`/`X-Approver-Signature` headers.
  See [INV-ADMIN-DUAL-APPROVAL](./index.mdx#dual-approval-gate--why-some-buttons-require-a-second-person).
- ❌ denied.
- self only — operation is permitted only against the actor's own account
  (e.g. mint a PAT for yourself).

> **Note (v1, manual):** This matrix is hand-maintained from
> `crates/corelink-pat/src/scopes.rs` and
> `crates/corelink-dual-approval/src/types.rs`. A future iteration will
> auto-generate via a `scripts/codegen_rbac_matrix.py` reader so the table
> cannot drift from code (planned for S-19).

## CAS — cache surface

| Permission                  | Scope                 | Owner | Admin | Developer | Viewer |
|-----------------------------|-----------------------|:-----:|:-----:|:---------:|:------:|
| Read CAS blobs + AC         | `cache:r`             |   ✅  |   ✅  |     ✅     |   ✅   |
| Write CAS blobs + AC        | `cache:w`             |   ✅  |   ✅  |     ✅     |   ❌   |
| FindMissingBlobs            | `cache:find-missing`  |   ✅  |   ✅  |     ✅     |   ❌   |
| Admin blob deletion         | `cache:delete`        |   ✅  |   ✅  |     ❌     |   ❌   |

:::warning[How the administrative rows are actually gated]
The **Scope** column below said `admin:tenant-read`, `admin:tenant-write`,
`admin:tokens`, `admin:audit` and `admin:users` for the administrative
rows. **Those six scopes were never implemented and were removed**
(B-080): no mint path accepted them, `pat.scope` could not store them,
and no enforcement point read them. Do not build a least-privilege plan
on those names.

Administrative access is gated on the **dashboard session role** (Clerk
owner/admin), shown here as `session role`, plus the `billing` capability
the Worker forwards for billing / account-PII. PAT scopes govern the
cache surface (`cache:*`) and the owner-grade `admin` superset.

The role columns describe the intended RBAC model. Parts of the admin
API they reference are not yet served — treat the ✅/❌ cells as the
design, and the [permissions reference](../../reference/rbac/permissions.mdx)
as the authority on what a PAT scope actually grants today.
:::
