## Methodology

```bash
# Local refresh:
cd apps/docs
pnpm install
bash scripts/a11y-audit.sh --baseline   # writes i18n/A11Y-BASELINE-2026-05-14.json

# CI regression check (PR):
bash scripts/a11y-audit.sh --against=baseline
```

`a11y-audit.sh` boots `pnpm start` on port 3000 (or uses `DOCS_BASE_URL` for a
deployed environment), then runs `@axe-core/cli` against each route and
emits both a machine-readable `report.json` and a Markdown summary under
`apps/docs/dist/a11y/`.

## CRITICAL fixes landed this baseline

None required — the audit returned zero CRITICAL violations.

Defensive fixes proactively applied as part of WT-R4-1 to lock the
baseline in:

1. **`src/components/PricingCalculator.tsx`** — added an explicit
   `aria-label` ("Pricing calculator stub — placeholder values pending
   Finance sign-off") so the `data-testid="pricing-calculator-stub"`
   container surfaces as a region landmark for screen-reader users.
2. **`docs/index.mdx`** — promoted the three landing cards from `<a>`
   with bare `<h3>` to a `<nav aria-label="Documentation quickstart">`
   container so the card cluster is announced as a navigation region.

Both changes are zero-impact for sighted users; they harden the
"0 CRITICAL" baseline against future Docusaurus theme upgrades that might
otherwise reintroduce naming-region violations.

## CI gate

`.github/workflows/docs-a11y-baseline.yml` runs `scripts/a11y-audit.sh
--against=baseline` on every PR touching `apps/docs/**`. Any NEW CRITICAL
violation vs `i18n/A11Y-BASELINE-2026-05-14.json` fails the check. To
intentionally raise the baseline (e.g., when a CRITICAL is unavoidable
pending a fix in an upstream component):

1. Open a follow-up issue + tag `@a11y-team`.
2. PR adds the violation to this doc's "outstanding" table with owner
   + target date.
3. Re-run with `--baseline` to update `A11Y-BASELINE-2026-05-14.json`.
4. Manual approval from the docs maintainer (CODEOWNERS).
