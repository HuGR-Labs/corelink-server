# SBOM access

> **DRAFT — pending Legal + Finance + Security review.** The procurement path
> below describes the *intended* customer-facing process; it is not yet
> contractually offered.

## What we publish

- **Format:** CycloneDX 1.5+ JSON (canonical per ADR-0014). SPDX 2.3+ available
  on request.
- **Cadence:** generated on every release build. **Not signed** — see
  "Signature verification" below.
- **Coverage:** Worker, Container, and CLI binaries — Rust crates and JS deps
  inclusive.

## How enterprise customers request the SBOM

1. Open a support ticket of type **"Procurement / Security Review"**.
2. Provide your account ID and the release version you need the SBOM for.
3. We respond within TBD business days with a time-limited download URL.

## Signature verification

**There is no SBOM signature to verify today, and we would rather say so than
print a command that cannot work.** No CoreLink release signing key has ever
been published, and no Sigstore/Rekor entry has ever been created for a CoreLink
artifact — the signing workflow was removed on 2026-08-31 after review
established it had never executed. This page previously carried an illustrative
`cosign verify-blob` snippet against a `$TBD` key URL; it has been removed rather
than left to imply a capability that does not exist.

What you *can* verify today: the SBOM is CycloneDX 1.5+ JSON and validates
against the CycloneDX schema, and the CLI build is reproducible — rebuilding the
published tag yields a byte-identical binary.

## Cross-functional review checklist

- [ ] Security Lead — confirm SBOM scope and signing key URL.
- [ ] Legal — confirm NDA or licensing terms gating distribution.
- [ ] Procurement — confirm SLA on ticket response time.
