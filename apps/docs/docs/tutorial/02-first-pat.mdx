# Create your first PAT

CoreLink authenticates every cache read and write with a personal access token (PAT). PATs are tenant-scoped, never leave the admin UI in plaintext after creation, and use the canonical format documented in the [auth model](../reference/reapi/index.mdx).

## 1. Sign up

1. Open [https://humangr.com/corelink/sign-up](https://humangr.com/corelink/sign-up) and create an account (Clerk-backed; SSO available on the Team plan).
2. Confirm your email; you land on the **Org overview** page.
3. Pick a tenant slug — the slug becomes the subdomain `<slug>.corelink.humangr.com`.

## 2. Create the PAT

1. In the admin UI sidebar, choose **Settings → Tokens**.
2. Click **New PAT**.
3. Pick:
   - **Environment**: the parser-defined literal `pat`, `ci`, or `ro`.
   - **Scope**: `cache:read`, `cache:write`, or both.
   - **Expiry**: 30 / 90 / 365 days (or custom).
4. Click **Create**. The token is shown **once** — copy it.

For a dedicated CI token after you have your starter PAT, call the same
self-service surface directly. The caller's tenant is derived from the
credential; never send a tenant ID or an operator mint key.

```bash
curl -X POST https://corelink-api.humangr.com/v1/pats \
  -H "Authorization: Bearer $CORELINK_PAT" \
  -H "Content-Type: application/json" \
  --data '{"label":"ci-runner","scopes":["cache:read","cache:write"]}'
```

The response returns `token` exactly once. Store it immediately; self-service
tokens expire after 90 days and cannot be granted `admin`.

## 3. Token format

CoreLink PATs follow the canonical format defined in the spec:

```
corelink_<env>_<token_id>.<random_secret>.<hmac_sig>
```

Example shape (synthetic; it is not a credential and its signature is not valid):

```
corelink_pat_0123456789ABCDEF.AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA.BBBBBBBBBBBBBBBBBBBBBA
```

Before sending a copied value, the CLI validates this shape locally with
`corelink login --token "$CORELINK_PAT"`. A malformed value is rejected before
any network request; the server still uses one opaque 401 response for all
authentication failures so it does not reveal which token component failed.

:::warning Never commit a real PAT
The placeholder `corelink_pat_0123456789ABCDEF.AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA.BBBBBBBBBBBBBBBBBBBBBA` is intentional. Real PATs must live in environment variables, secret managers, or your CI provider's secret store — never in source code.
:::

## 4. Export it

```bash
export CORELINK_PAT="corelink_pat_0123456789ABCDEF.AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA.BBBBBBBBBBBBBBBBBBBBBA"  # replace with your real token
```

Add the line to your shell profile (`~/.zshrc`, `~/.bashrc`) for persistence, or load it through a secret manager (`direnv`, `1password`, `op`).

## 5. Verify

```bash
corelink doctor --check-auth
# OK — PAT valid, tenant=acme-dev, scopes=[cache:read,cache:write], expires in 90d
```
