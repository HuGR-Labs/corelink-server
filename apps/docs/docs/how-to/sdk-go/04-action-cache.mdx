# Action Cache

## When to use this guide

You want to cache the result of a build action — exit code, stdout, output
files — keyed by an action digest, and look it up before re-running the
action.

## `Client.ActionCache()`

`corelink.Client` exposes the REAPI v2 action cache through
`Client.ActionCache()`, which returns an `*corelink.ActionCacheClient` with
two methods:

```go
ac := client.ActionCache()

// Update stores an ActionResult for an action digest.
err := ac.Update(ctx, actionDigest, corelink.ActionResult{
    ExitCode: 0,
    OutputFiles: []corelink.OutputFile{
        {Path: "bin/app", Digest: outputDigest, IsExecutable: true},
    },
})

// Get returns a cached ActionResult, or corelink.ErrActionCacheMiss.
result, err := ac.Get(ctx, actionDigest)
```

`Update` writes to `PUT /bazel/v2/{instance}/blobs/ac/{hash}/{size}`; `Get`
reads from the same path. Both operate against `Config.Instance` — set it on
the `Config` you pass to `NewClient` when you construct the client, the same
way you would configure a Bazel remote-cache instance name.

## Handling a cache miss

A miss is not an error you branch on by string. Match the sentinel with
`errors.Is`:

```go
result, err := ac.Get(ctx, actionDigest)
switch {
case errors.Is(err, corelink.ErrActionCacheMiss):
    result, err = runActionAndStore(ctx, ac, actionDigest)
    if err != nil {
        return err
    }
case err != nil:
    return fmt.Errorf("action cache lookup: %w", err)
}
```

## Encoding

The server stores the Action Cache payload as an opaque byte blob — it does
not parse it. `ActionCacheClient.Update` and `.Get` own the encoding
themselves (a private JSON shape), so `ActionResult` round-trips through
this SDK without you writing any serialization code. A payload written by a
different client (the JS/TS SDK, or a raw HTTP call) uses its own encoding
and will not decode as an `ActionResult` here.
