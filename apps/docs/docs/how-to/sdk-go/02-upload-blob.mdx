# Upload a blob

## When to use this guide

You have a `[]byte` and want it persisted into the CoreLink CAS. `Put`
computes the BLAKE3 digest for you — there is no way to supply a
pre-computed digest client-side in this SDK (unlike `corelink-py`'s
`expected_digest=`).

## Prerequisites

- Authentication configured ([01-authenticate](./01-authenticate.mdx)).

## Minimal example

```go
import (
    "context"
    "os"

    "github.com/HumanGuardrail/corelink-go/v1"
)

func upload(ctx context.Context, cli *corelink.Client, path string) (string, error) {
    data, err := os.ReadFile(path)
    if err != nil {
        return "", err
    }
    return cli.Put(ctx, data)
}
```

## No streaming upload

`Client` has exactly three data-plane methods — `Put`, `Get`, `Stat` — and
`Put` takes a `[]byte`, not an `io.Reader`; there is no `PutStream` or
chunk-size option. For a file too large to hold fully in memory, read it in
your own chunks and assemble the upload yourself, or use `corelink-py`'s
`put_stream(fileobj, chunk_size=...)` (both the sync and async Python
clients have it), which streams from an open file handle without buffering
the whole thing.

## Idempotency

The native CAS is content-addressed: two `Put` calls with identical bytes
resolve to the same digest, so a duplicate upload is not billed as separate
storage.

## Context plumbing

`Put`'s `context.Context` parameter is accepted for API shape but is
**not currently wired to cancellation** — the parameter is discarded
(`func (c *Client) Put(_ context.Context, data []byte) ...`,
`corelink-go/corelink.go:160`). Passing a cancelled or timed-out context
does not abort an in-flight `Put`; if you need a hard timeout, enforce it
around the call yourself (for example, run it in a goroutine and select on
`ctx.Done()`).

## Errors

`Client` methods return plain `error` values (message strings), not a
typed error hierarchy — there is no `*corelink.AuthError`,
`*corelink.QuotaError`, or similar type to type-switch on. Match on the
message instead:

| Message contains | Cause | Action |
|---|---|---|
| `put failed (rc=%d)` | The native `Put` call returned non-zero — could be network, auth, or quota | Confirm the PAT/tenant with a `Stat` call first; if that also fails, see [Troubleshooting](./07-troubleshooting.mdx) |
