# CI integration

## When to use this guide

Your build is a Go project (or its smoke tests are written in Go) and you
want CoreLink as a shared cache without shelling out to the CLI.

## GitHub Actions

```yaml
# .github/workflows/build.yml
jobs:
  build:
    runs-on: ubuntu-latest
    env:
      CORELINK_PAT: ${{ secrets.CORELINK_PAT }}
      GOPROXY: https://humangr.com/corelink/docs/goproxy,https://proxy.golang.org,direct
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-go@v5
        with:
          go-version: "1.22"
      - run: go get go.corelink.humangr.com/corelink-go@v0.1.0  # GOPROXY set above
      - run: go run ./ci/warm-cache
```

```go
// ci/warm-cache/main.go
package main

import (
    "context"
    "log"
    "os"

    "go.corelink.humangr.com/corelink-go"
)

func main() {
    ctx := context.Background()
    cli, err := corelink.NewClient(corelink.Config{
        Endpoint: "https://corelink-api.humangr.com",
        PAT:      os.Getenv("CORELINK_PAT"),
        TenantID: os.Getenv("CORELINK_TENANT"),
    })
    if err != nil {
        log.Fatal(err)
    }
    defer cli.Close()

    // Warm the cache with a real Put/Get round trip and fail the job on error.
    digest, err := cli.Put(ctx, []byte("ci-warm-cache-probe"))
    if err != nil {
        log.Fatalf("cache warm-up failed: %v", err)
    }
    if _, err := cli.Get(ctx, digest); err != nil {
        log.Fatalf("cache verify failed: %v", err)
    }
    log.Println("cache reachable")
}
```

## GitLab CI

```yaml
build:
  image: golang:1.22
  variables:
    CORELINK_PAT: $CORELINK_PAT  # masked
    GOPROXY: "https://humangr.com/corelink/docs/goproxy,https://proxy.golang.org,direct"
  script:
    - go get go.corelink.humangr.com/corelink-go@v0.1.0  # GOPROXY set above
    - go run ./ci/warm-cache
```

## CircleCI

```yaml
version: 2.1
jobs:
  build:
    docker:
      - image: cimg/go:1.22
    environment:
      CORELINK_PAT: $CORELINK_PAT
      GOPROXY: https://humangr.com/corelink/docs/goproxy,https://proxy.golang.org,direct
    steps:
      - checkout
      - run: go get go.corelink.humangr.com/corelink-go@v0.1.0  # GOPROXY set above
      - run: go run ./ci/warm-cache
```

## Job-scoped PATs

Mint a dedicated CI token instead of reusing a personal one: `POST
/v1/customer/keys` with `{"name": "ci-<repo>", "scopes": ["cas:rw"]}`, or the
**Keys** page in the dashboard. The token comes back once — inject it via your
CI provider's secret store as shown above.

Note what "job-scoped" can and cannot mean here: the mint API takes a name and
scopes, and **no expiry** (`CreatePatBody`,
`crates/corelink-container/src/routes/customer.rs:463`). There is no
self-expiring per-pipeline token. A short-lived credential is mint-then-revoke —
`POST /v1/customer/keys/{pat_id}/revoke` — both of which are self-service and
both of which need a cache-write capability. See
[Security model](../../security.md).
