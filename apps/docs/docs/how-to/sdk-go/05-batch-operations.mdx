# Batch operations

## When to use this guide

You have many small blobs to push and want to saturate available bandwidth
without exceeding the server-side per-PAT concurrency limit.

## Pattern: Bounded `errgroup`

```go
import "golang.org/x/sync/errgroup"

func uploadMany(ctx context.Context, cli *corelink.Client, paths []string,
    concurrency int,
) ([]string, error) {
    g, gctx := errgroup.WithContext(ctx)
    g.SetLimit(concurrency)
    digests := make([]string, len(paths))
    for i, p := range paths {
        i, p := i, p
        g.Go(func() error {
            data, err := os.ReadFile(p)
            if err != nil {
                return err
            }
            d, err := cli.Put(gctx, data)
            if err != nil {
                return err
            }
            digests[i] = d
            return nil
        })
    }
    if err := g.Wait(); err != nil {
        return nil, err
    }
    return digests, nil
}
```

`concurrency=32` is a reasonable starting point; back off if you see repeated
failures.

## No built-in retry or rate-limit handling

`Client` does not retry anything itself, has no `*corelink.RateLimitError`
type, no `WithRetryPolicy` option, and `NewClient` takes a single `Config`
struct — there's no `corelink.NewClient(ctx, corelink.WithTenantID(...), ...)`
functional-options form (see [Authenticate](./01-authenticate.mdx)). If a
`Put`/`Get` call in the loop above fails, `errgroup` surfaces the plain
`error` string; you own the retry loop:

```go
for attempt := 0; ; attempt++ {
    if _, err := cli.Put(gctx, data); err != nil {
        if attempt >= 4 {
            return err
        }
        time.Sleep(time.Duration(1<<attempt) * time.Second) // 1s, 2s, 4s, 8s
        continue
    }
    break
}
```

Because the error is an unstructured string, this retries on *any* failure
(network, auth, quota) the same way — there's no way to isolate "rate
limited" specifically from this SDK today.

## Pre-dedupe before upload

`Put` has no `expected_digest`/`WithExpectedDigest` option (unlike
`corelink-py`'s `put(data, expected_digest=...)`) — it always computes the
digest itself. Client-side pre-dedup here is purely a local optimization to
skip redundant `Put` calls within one run; it does not skip a network round
trip the way passing a pre-computed digest would:

```go
func uploadDedup(ctx context.Context, cli *corelink.Client, paths []string) (map[string]string, error) {
    seen := map[string]bool{}
    digests := map[string]string{}
    for _, p := range paths {
        data, err := os.ReadFile(p)
        if err != nil {
            return nil, err
        }
        // Local hash purely to decide whether to call Put again this run —
        // Put still recomputes BLAKE3 itself server-side/native-side. Use
        // whichever Go BLAKE3 package you've already vendored (this SDK
        // itself doesn't expose a standalone hash function); a SHA-256 or
        // any other stable local hash works equally well for this
        // in-process dedup check since it's never sent to the server.
        hex := localHash(data)
        if seen[hex] {
            continue
        }
        seen[hex] = true
        digest, err := cli.Put(ctx, data)
        if err != nil {
            return nil, err
        }
        digests[p] = digest
    }
    return digests, nil
}

// localHash is a stand-in for whatever hash function you already have
// available (a BLAKE3 or SHA-256 package of your choosing) — it only needs
// to be stable within one run, since it's used purely to skip redundant
// local Put calls and is never sent to the server.
func localHash(data []byte) string {
    sum := sha256.Sum256(data)
    return hex.EncodeToString(sum[:])
}
```
