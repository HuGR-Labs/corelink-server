# CI integration

## When to use this guide

Your test or build pipeline already uses Python and you want to use CoreLink
as a build-output cache without rewriting steps in another language.

## GitHub Actions

```yaml
# .github/workflows/build.yml
jobs:
  build:
    runs-on: ubuntu-latest
    env:
      CORELINK_PAT: ${{ secrets.CORELINK_PAT }}
      CORELINK_TENANT: ${{ vars.CORELINK_TENANT }}
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: "3.11"
      - run: pip install --extra-index-url https://humangr.com/corelink/docs/pypi/simple/ --pre corelink-py
      - run: python ./ci/warm_cache.py
```

Store the PAT as a repository secret named `CORELINK_PAT`. Do not echo it.

```python
# ci/warm_cache.py
import asyncio
import os
import sys

from corelink import AsyncCoreLinkClient

async def main() -> int:
    # There is no bench() method on this SDK — warm the cache with a real
    # put/get round trip and fail the job on error.
    async with AsyncCoreLinkClient(tenant_id=os.environ["CORELINK_TENANT"]) as c:
        digest = await c.put(b"ci-warm-cache-probe")
        await c.get(digest)
    print("cache reachable")
    return 0

sys.exit(asyncio.run(main()))
```

## GitLab CI

```yaml
build:
  image: python:3.11
  variables:
    CORELINK_PAT: $CORELINK_PAT  # masked CI variable
    CORELINK_TENANT: $CORELINK_TENANT  # project variable
  script:
    - pip install --extra-index-url https://humangr.com/corelink/docs/pypi/simple/ --pre corelink-py
    - python ./ci/warm_cache.py
```

## CircleCI

```yaml
version: 2.1
jobs:
  build:
    docker:
      - image: cimg/python:3.11
    environment:
      CORELINK_PAT: $CORELINK_PAT
      CORELINK_TENANT: $CORELINK_TENANT
    steps:
      - checkout
      - run: pip install --extra-index-url https://humangr.com/corelink/docs/pypi/simple/ --pre corelink-py
      - run: python ./ci/warm_cache.py
```

## Job-scoped PATs (recommended)

Mint a dedicated CI token instead of reusing a personal one: `POST
/v1/customer/keys` with `{"name": "ci-<repo>", "scopes": ["cas:rw"]}`, or the
**Keys** page in the dashboard. The token comes back once — inject it via your
CI provider's secret store as shown above. Set `CORELINK_TENANT` to the
repository/project variable containing the tenant ID; the Python SDK requires
it for tenant-addressed CAS operations.

The mint API takes a name and scopes, but has no caller-selected expiry.
Customer-issued PATs expire after 90 days, so there is no self-expiring
per-pipeline token. For a shorter job lifetime, mint then revoke with `POST
/v1/customer/keys/{pat_id}/revoke`; write-capable minting needs cache-write and
revocation needs a server-trusted owner/admin team role. See [Security
model](../../security.md).
