# Batch operations

## When to use this guide

You have hundreds to millions of small blobs to upload in one pass (for
example, a remote-build worker draining its local cache) and want maximum
throughput without tripping CoreLink's per-tenant rate limits.

If you have a single large blob, prefer streaming
([02-upload-blob](./02-upload-blob.mdx)).

## Pattern: Bounded `asyncio.gather`

Use the **async** client for this — `CoreLinkClient` is synchronous and
cannot be awaited or used with `async with` (see
[Authenticate](./01-authenticate.mdx)):

```python
import asyncio
from pathlib import Path
from corelink import AsyncCoreLinkClient

async def upload_many(paths: list[Path], concurrency: int = 32) -> list[str]:
    sem = asyncio.Semaphore(concurrency)
    async with AsyncCoreLinkClient(tenant_id="acme-corp") as client:
        async def one(p: Path) -> str:
            async with sem:
                return await client.put(p.read_bytes())
        return await asyncio.gather(*(one(p) for p in paths))
```

`concurrency=32` is a reasonable starting point; back off if you see
repeated `CoreLinkRequestError`s.

## No built-in retry or rate-limit handling

There is no `RateLimitError` type and no `RetryPolicy` — `CoreLinkClient` /
`AsyncCoreLinkClient` do not retry anything themselves. A `429` response
surfaces as `CoreLinkRequestError` with `status_code == 429` (the generic
4xx-except-401 exception — see
[sdks/python/corelink/exceptions.py](https://github.com/HumanGuardrail/corelink-server/blob/main/sdks/python/corelink/exceptions.py)),
indistinguishable from any other client error except by that attribute.
You own the retry loop:

```python
import asyncio
from corelink.exceptions import CoreLinkRequestError

async def put_with_backoff(client, data: bytes, max_attempts: int = 5) -> str:
    for attempt in range(max_attempts):
        try:
            return await client.put(data)
        except CoreLinkRequestError as e:
            if e.status_code != 429 or attempt == max_attempts - 1:
                raise
            await asyncio.sleep(2 ** attempt)  # 1s, 2s, 4s, 8s, 16s
    raise RuntimeError("unreachable")
```

## Pattern: Digest-keyed dedupe before upload

`put`'s `expected_digest=` is real (unlike the Go SDK, which has no
equivalent) — computing the digest yourself and passing it skips the SDK's
own re-hash pass, though the server still verifies it server-side:

```python
import blake3

async def upload_dedup(client, paths: list[Path]) -> dict[str, str]:
    seen: dict[str, str] = {}
    for p in paths:
        data = p.read_bytes()
        d = blake3.blake3(data).hexdigest()
        if d in seen:
            continue
        seen[d] = await client.put(data, expected_digest=d)
    return seen
```

This cuts re-hashing work (not upload count — the server still re-checks
every claimed digest) on runs that see the same bytes repeatedly.
