# Action Cache

## The Python SDK does not implement an Action Cache client

`corelink-py` (`corelink.client.CoreLinkClient` and
`corelink.aio.AsyncCoreLinkClient`) implements the CAS data plane (`put` /
`put_stream` / `get` / `stat`) and the control plane (`get_health` /
`issue_pat` / `signup`) — there is no `action_cache` attribute, no
`ActionCache` type, and no REAPI v2 wrapper in this SDK today.

If you need Action Cache from JS/TS, use `@corelink/client`, which does
implement it (`client.actionCache.get` / `.put`) — see the
[JS/TS Action Cache guide](../sdk-js/04-action-cache.mdx).

## Working around it from Python today

The Action Cache is a real server surface (`routes/ac.rs`, REAPI v2) even
though this SDK doesn't wrap it — you can call it directly over HTTP with
the same PAT you already configured:

```python
import httpx
from corelink.client import CoreLinkClient

def get_or_run(client: CoreLinkClient, action_digest: str) -> bytes:
    resp = httpx.get(
        f"{client._base_url}/v1/ac/{client._tenant_id}/{action_digest}",
        headers={"Authorization": f"Bearer {client._pat}"},
    )
    if resp.status_code == 404:
        return run_locally_and_store(client, action_digest)
    resp.raise_for_status()
    return resp.content  # opaque ActionResult bytes — you own the encoding
```

The Action Cache stores an opaque byte payload keyed by a 64-hex action
digest — the server does not parse it, so how you encode/decode the
`ActionResult` (a serialized REAPI message, your own JSON manifest
referencing CAS blobs by digest, etc.) is up to you, same as the JS SDK.
