# Action Cache lookup and store

## When to use this guide

You wrap a JS-driven test runner (e.g. Jest, Vitest, Playwright) with a
build-cache layer and want hit/miss semantics keyed by an Action digest.

If you only need raw CAS, see
[02-upload-blob](./02-upload-blob) and
[03-download-blob](./03-download-blob).

## The AC payload is opaque bytes

CoreLink stores an **opaque `ActionResult` byte payload** keyed by a 64-hex
action digest (`routes/ac.rs`). The SDK moves those bytes verbatim — you own
the encoding (e.g. a serialized REAPI `ActionResult` protobuf, or your own JSON
manifest referencing CAS blobs by digest). `actionCache.get` returns a
`Uint8Array`; `actionCache.put` takes one.

## Lookup

```typescript
import { ActionCacheMiss } from "@corelink/client";

async function getOrRun(actionDigest: string): Promise<Uint8Array> {
  try {
    const resultBytes = await client.actionCache.get(actionDigest);
    const manifest = JSON.parse(new TextDecoder().decode(resultBytes));
    return client.get(manifest.stdoutDigest); // fetch the referenced CAS blob
  } catch (e) {
    if (e instanceof ActionCacheMiss) {
      return runLocallyAndStore(actionDigest);
    }
    throw e;
  }
}
```

## Store

```typescript
async function storeResult(
  actionDigest: string,
  stdout: Uint8Array,
  exitCode: number,
): Promise<void> {
  const stdoutDigest = await client.put(stdout);
  const manifest = { stdoutDigest, exitCode };
  const bytes = new TextEncoder().encode(JSON.stringify(manifest));
  await client.actionCache.put(actionDigest, bytes);
}
```

## Immutability & cache-poisoning protection

AC entries are content-immutable: the server rejects a divergent overwrite of an
existing `(tenant, action_digest)` with `409`, surfaced as `ConflictError`. A
byte-identical re-store is an idempotent no-op.
