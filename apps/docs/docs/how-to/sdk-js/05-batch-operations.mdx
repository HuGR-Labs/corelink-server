# Batch operations

## When to use this guide

You have many blobs to push or pull and want to saturate available
bandwidth without exceeding the server-side per-PAT limit (256 concurrent).

## Pattern: Bounded `Promise.all`

```typescript
import pLimit from "p-limit";
import { readFile } from "node:fs/promises";

async function uploadMany(
  paths: string[],
  concurrency = 32,
): Promise<string[]> {
  const limit = pLimit(concurrency);
  return Promise.all(
    paths.map((p) =>
      limit(async () => {
        const data = await readFile(p);
        return client.put(data);
      }),
    ),
  );
}
```

## Rate-limit handling

`RateLimitError` (429) and 503 are auto-retried with exponential backoff +
jitter (3 attempts by default, each backoff capped at `maxDelayMs`). Customize:

```typescript
const client = new CoreLinkClient({
  tenantId: "acme-corp",
  retry: { maxAttempts: 5, baseDelayMs: 200, maxDelayMs: 10_000 },
});
```

When attempts are exhausted, drain pending work and stop submitting.

## Pattern: Digest-keyed dedupe

```typescript
import { blake3Hex } from "@corelink/client";

async function uploadDedup(
  paths: string[],
): Promise<Record<string, string>> {
  const seen: Record<string, string> = {};
  for (const p of paths) {
    const data = await readFile(p);
    const hex = blake3Hex(data); // same digest the server addresses the blob by
    if (hex in seen) continue;
    seen[hex] = await client.put(data, { expectedDigest: hex });
  }
  return seen;
}
```

Cuts upload count by 60-90% on typical build outputs.
