# Upload a blob

## When to use this guide

You have a `Uint8Array` or a Node `Buffer` (which is a `Uint8Array`) and want it
persisted in the CoreLink CAS. The SDK computes the BLAKE3 digest for you; you
may optionally pass an `expectedDigest` to assert it matches locally.

## Prerequisites

- Authentication configured ([01-authenticate](./01-authenticate.mdx)).

## Minimal example

```typescript
import { CoreLinkClient } from "@corelink/client";
import { readFile } from "node:fs/promises";

const client = new CoreLinkClient({ tenantId: "acme-corp" });
const data = await readFile("./build/output.tar");
const digest = await client.put(data);
console.log("stored:", digest);
await client.close();
```

`digest` is the 64-character BLAKE3 hex string.

## Large blobs

`put` takes the full byte array (a content-addressable store must hash the
whole object to know its address, so the digest is computed over the complete
buffer). Read the file into memory, then upload:

```typescript
import { readFile } from "node:fs/promises";

async function uploadLarge(path: string): Promise<string> {
  const data = await readFile(path); // Buffer is a Uint8Array
  return client.put(data);
}
```

A chunked/streaming upload API is not part of this release.

## Idempotency

`put` deduplicates server-side; two uploads of identical bytes resolve to
the same digest without double-billing.

## TypeScript types

The package ships full `.d.ts` declarations:

```typescript
import type { BlobDigest, TenantId, PutOptions } from "@corelink/client";

const opts: PutOptions = { expectedDigest: "..." satisfies BlobDigest };
```
