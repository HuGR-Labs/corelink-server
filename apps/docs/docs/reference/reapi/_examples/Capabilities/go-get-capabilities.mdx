# Go — `Capabilities.GetCapabilities` is not available

`Client.Capabilities` exists on the SDK's type surface, but there is no
server endpoint behind it. The REAPI v2 route table
(`crates/corelink-container/src/routes/bazel_v2.rs`) mounts exactly five
routes — CAS read, CAS write, AC read, AC write, and `findMissingBlobs` —
and none of them is a capabilities surface. `Capabilities` makes no network
call; it returns the zero-value `ServerCapabilities` and an error explaining
why.

## Code

```go
package main

import (
    "context"
    "fmt"
    "os"

    corelink "go.corelink.humangr.com/corelink-go"
)

func main() {
    ctx := context.Background()
    client, _ := corelink.NewClient(corelink.Config{
        Endpoint: "https://corelink-api.humangr.com",
        PAT:      os.Getenv("CORELINK_PAT"),
    })
    defer client.Close()

    _, err := client.Capabilities(ctx)
    fmt.Println(err)
}
```

## Expected output

```text
corelink: no REAPI Capabilities endpoint exists on this server (bazel_v2.rs mounts only CAS read/write, AC read/write, and findMissingBlobs); use Client.Health for a readiness check instead
```

## What to use instead

Use `Client.Health` for a readiness check (see the
[Health · Check example](../Health/go-check.mdx)). To pick a digest
function without a negotiation endpoint, see
[pick a digest function](./go-pick-digest.mdx).
