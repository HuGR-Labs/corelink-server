# `POST` `/v1/dpa/re-accept`

> Re-accept a major-bumped DPA notice within the 30-day grace window.

- **Operation ID:** `dpaReAccept`
- **Tag:** `dpa`
- **Rate-limit class:** default (600 req/min/PAT)

## Description

When a new DPA version is published the tenant enters a 30-day grace
window; `corelink-dpa-versioning` middleware flips writes to read-only
until the customer self-recovers via this endpoint.

## Authentication

- `BearerPAT`
- `ClerkSessionCookie`

## Parameters

_None._

## Request body

- **Media type:** `application/json`
- **Required:** yes
- **Schema:** [`DpaAcceptanceRequest`](#schema-dpaacceptancerequest)

## Responses

| Status | Schema | Description |
| --- | --- | --- |
| `201` | [`DpaAcceptanceReceipt`](#schema-dpaacceptancereceipt) | Re-acceptance recorded; tenant returns to read-write. |
| `401` | [`ErrorEnvelope`](#schema-errorenvelope) | Missing or invalid credentials. |
| `403` | [`ErrorEnvelope`](#schema-errorenvelope) | Grace window expired; tenant is now read-only-frozen and requires manual unfreeze via admin. |
| `422` | [`ErrorEnvelope`](#schema-errorenvelope) | Schema-valid but semantically invalid payload. |
| `500` | [`ErrorEnvelope`](#schema-errorenvelope) | Server error. Safe to retry idempotent operations. |
