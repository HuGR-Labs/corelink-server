# `POST` `/v1/customer/keys`

> Issue a new Personal Access Token.

- **Operation ID:** `customerKeysCreate`
- **Tag:** `pat`
- **Rate-limit class:** pat-issue (10 req/hour/tenant)

## Description

<<<<<<< HEAD:apps/docs/docs/reference/api/endpoints/post-v1-pats.mdx
Creates a PAT for the caller's authenticated tenant. Browser/dashboard
callers authenticate with an edge-validated Clerk session cookie; CLI
callers may use a canonical PAT for compatibility. The Worker derives
the tenant from that verified credential; clients
cannot supply a tenant id and this endpoint never accepts the
operator-only mint authority. The raw token is returned exactly once in
`token` and is never logged or retrievable later. Self-service tokens
expire after 90 days and cannot grant `admin`.
This endpoint and the legacy dashboard alias `POST /v1/customer/keys`
use the same customer-plane mint flow and the same per-tenant
`pat-issue` bucket: burst 10, then 10 tokens per hour (one every 360
seconds). The limiter runs before mint and audit; a denied request
returns `429` with `Retry-After`.
=======
Returns the raw token material **once**, in the `token` field. The
token is hashed before storage; every subsequent read returns metadata
only.

Minting a credential that carries any write/admin scope requires the
caller to already hold a cache-write capability — a read-only token
cannot bootstrap a write token for itself (`403`).
