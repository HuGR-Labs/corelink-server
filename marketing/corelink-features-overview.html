Cache Surfaces & Compatibility

CoreLink is a single shared storage engine that plugs directly into the development tools teams already use, so their software builds run dramatically faster and cheaper without anyone installing or learning anything new.

Works with the tools teams already use
CoreLink connects to all the major build and packaging tools a software team already runs, by changing a single setting rather than installing anything new.
SolvesRemoves the cost, risk, and lock-in of adopting a proprietary tool, so customers can switch on the value in minutes with zero migration.
Store-once shared library of build results
It keeps a single copy of every unique piece of a software build and reuses it instead of producing or downloading it again.
SolvesEliminates the massive waste of teams rebuilding and re-downloading the same things over and over, cutting both wait time and storage cost.
Skip work that's already been done
When a build step has already been run by anyone on the team, CoreLink instantly returns the finished result instead of running it again.
SolvesTurns 'rebuild everything' into 'rebuild almost nothing,' saving hours of engineer and compute time on every run.
Faster builds for large codebases
It plugs into the build systems used by big engineering organizations so their automated testing and compiling reuse prior results across the whole team.
SolvesStops large teams from repeating enormous build workloads on every code change, directly reducing expensive build-server hours.
Drop-in replacement for paid caching services
It serves as a self-hosted alternative to the paid build-caching subscriptions some teams currently buy from outside vendors.
SolvesReplaces a recurring third-party bill and the slow no-cache fallback with a cache the customer fully controls.
Private container image registry
CoreLink acts as a private home for the packaged application images teams ship, deduplicating shared pieces between them.
SolvesSpares teams from standing up and maintaining their own registry while shrinking storage by sharing common layers.
Shared cache for programming-language packages
It mirrors and stores the common code libraries that languages like Rust, JavaScript, Python, and others pull in, so they're fetched once and reused.
SolvesStops every machine and automated job from re-downloading the same dependencies, speeding up setup and keeping builds working even when the public source is down.
One engine behind every tool
Every supported tool reads and writes through the same single storage engine rather than separate per-tool systems.
SolvesMeans every tool a team uses contributes to and benefits from the same shared cache, multiplying savings and lowering CoreLink's own running costs.
Network-effect shared cache for public content
Publicly available components are stored once and served to every customer, while each customer's private content stays isolated to them.
SolvesCreates a compounding advantage where each new customer makes the cache fuller, faster, and cheaper for everyone, a defensible moat a single-customer cache cannot match.
Tamper-proof content verification
Every item is checked against its expected fingerprint before it's stored and again when it's served back.
SolvesPrevents one customer from poisoning the shared cache with bad or malicious content, protecting everyone who relies on it.
Read-only and read-write access levels
Teams can hand out keys that only read from the cache versus keys that can also write to it, consistently across every tool.
SolvesLimits the damage of a leaked or stolen credential, since a read-only key can never corrupt the shared cache.
See and delete what's stored (privacy compliance)
Customers can list everything CoreLink holds for them and permanently erase specific items, with deleted content guaranteed never to come back.
SolvesSatisfies data-deletion obligations under privacy law and turns an opaque storage pile into something customers can audit and govern.

Fair-use protection in shared infrastructure

SolvesKeeps the service fast and stable for everyone and avoids the cost of building separate infrastructure for each customer.
Fail loudly, never lose data silently

SolvesTurns a configuration mistake into an obvious, fixable alert rather than silent data loss that breaks the durability customers pay for.

Content-Addressed Core & Network Effect

This is the engine that stores every piece of code and build output once, proves it hasn't been tampered with, and lets the shared system get faster and cheaper for everyone as more customers join.

Store-it-once deduplication
Recognizes when content is identical to something already stored and keeps just one copy instead of saving the same thing over and over.
SolvesEliminates the cost and time of repeatedly uploading and storing the same dependencies and build outputs, which is the core driver of being both faster and cheaper.
Tamper-proof fingerprinting
Gives every stored item a unique fingerprint derived from its actual contents, and refuses to trust any fingerprint that wasn't genuinely calculated from real data.
SolvesRemoves the risk that a bad actor could pass off fake or corrupted content as legitimate, turning a common security weakness into something the system simply cannot accept.
Verify-before-save guarantee
Checks that every piece of content actually matches its claimed fingerprint before it is ever saved, and blocks the save if it doesn't.
SolvesPrevents poisoned or mismatched content from being stored and later served to customers, protecting the integrity of everyone's shared cache.
Skip work that's already been done
Lets build tools reuse the finished result of a previous build step instead of recomputing it from scratch.
SolvesCuts out redundant recompilation, which is the single biggest source of wasted build time and infrastructure cost for engineering teams.
Smart handling of large files
Breaks big files into pieces in a way that, when only a small part changes, lets the system re-upload only the changed piece rather than the whole file.
SolvesAvoids re-shipping multi-gigabyte artifacts every time a tiny change is made, dramatically reducing bandwidth and storage cost for large binaries and machine-learning assets.
Customer-to-customer isolation
Keeps each customer's private content walled off so no one can even detect, let alone access, what another customer has stored.
SolvesCloses the trust gap that would otherwise make a shared system unsafe, ensuring confidential code and assets stay private.
Cryptographic ownership locking
Cryptographically ties each cached build result to the customer who created it, using a secret key that storage operators do not hold.
SolvesStops even a privileged insider with storage access from forging or swapping a customer's content, which is the central protection against tampering in a shared system.
Double-checked integrity
Independently re-verifies cached build results both when they are saved and again when they are downloaded.
SolvesMeans a single compromised point can't quietly slip corrupted content through, shielding customers from poisoned build outputs.
One universal format across all tools
Uses a single common fingerprinting standard so content stored by one type of build tool can be reused by completely different ones.
SolvesLets every tool contribute to and draw from the same shared pool, so the cache fills up faster and delivers more savings across the whole customer base.
Abuse and flood protection
Identifies and drops hostile traffic at the edge before it can consume any computing resources, and enforces strict size limits on incoming requests.
SolvesKeeps the service available and responsive for paying customers even when under attack, protecting both uptime and operating cost.
Cost-efficient cleanup of cold content
Tracks what is actually being used and safely removes stale, unused content while protecting anything still in demand.
SolvesKeeps storage costs bounded as the system scales, directly protecting the healthy operating margin of the product.
Faster repeat lookups
Remembers recent 'not found' answers so common repeated checks are resolved instantly instead of doing expensive full searches every time.
SolvesReduces latency and infrastructure load from repetitive lookups while carefully avoiding any wrong answer that could cause unnecessary uploads.
Measured savings reporting
Counts how much content is reused versus newly stored, producing a concrete measure of the savings the system delivers.
SolvesTurns the cost-savings story into something measured and provable rather than asserted, and flags when efficiency is slipping.
Tamper-evident, replayable audit chain
Records billing and usage events into a signed, hash-linked chain that customers and auditors can independently replay to detect tampering or gaps. (The customer activity log is best-effort; the signed chain is the tamper-evident record.)
SolvesProvides a cryptographically verifiable record that can be re-derived from first principles for compliance and due diligence, rather than a log that must be taken on trust.
Shared commons for public code (planned)
Envisions storing widely-used public, open-source dependencies a single time and sharing them safely across all customers while keeping private content isolated.
SolvesCreates a compounding advantage where each new customer makes builds faster and cheaper for everyone, a self-reinforcing moat a single-customer system can never match.

The capabilities below describe the planned design, not shipped functionality.

Speed-and-savings flywheel
By reusing work already done and stored in the shared cache, it cuts the time and computing power a typical build needs by roughly five to ten times.
SolvesBreaks the usual trade-off where faster builds cost more, so customers get speed while the company keeps a high profit margin on a low price.
Shared-cache network advantage
Common, publicly available software building blocks are stored once and reused across all customers, so the service gets faster and cheaper for everyone as more customers join.
SolvesCreates a durable competitive advantage that a smaller or single-customer rival cannot match, turning a commodity feature into a defensible moat.
Customer data isolation
Only public, identical-for-everyone building blocks are ever shared between customers, while each customer's private build results stay walled off to that customer.
SolvesRemoves the biggest risk of a shared system, a leak of one customer's private work to another, which is the one failure a multi-customer service can never afford.

Build machines start up on demand for each job, run the work, and shut down immediately, so customers only pay for compute while a build is actually happening.
SolvesEliminates the wasted cost of paying for idle reserved capacity, which is what normally erodes the profitability of build services.

Customers pay a simple flat fee based on how many builds they want to run at the same time, with no per-minute charges and the cache included for free.
