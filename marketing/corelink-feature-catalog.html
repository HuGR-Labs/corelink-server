Cache Surfaces & Protocol Compatibility 23

One content-addressed store, many native protocols — point your existing tool's flag at CoreLink.

CoreLink is fundamentally ONE multi-tenant content-addressable store (R2 + D1 + the 2-level "moat") fronted by MANY native client cache protocols, so a customer points an existing tool's flag (`--remote_cache=`, `TURBO_API=`, `RUSTC_WRAPPER=sccache` WebDAV, `docker push`, `~/.cargo`) at CoreLink and gets faster + cheaper CI with zero proprietary client. Surfaces actually wired + mounted in the container (crates/corelink-container/src/routes.rs:545-676): native CAS (`/v1/cas`, BLAKE3) and AC (`/v1/ac`), Bazel REAPI v2 REST bridge (`/bazel/v2`, SHA-256), Turborepo v8 (`/v8/artifacts`, opaque hash), OCI Distribution v1.1 registry (`/v2` + `/token`, sha256 digest mapped to BLAKE3 in the moat), and the cargo/sccache (`/cargo`, HTTP/WebDAV), Homebrew (`/brew`), npm (`/npm`), and PyPI/pip (`/pip`) read-through caches. All write surfaces share ONE storage chokepoint with identical tenant-isolation, scope, native-PAT-possession, $-ceiling and byte-accounting gates, plus per-tenant pre-body concurrency caps. The digest scheme forks per surface (BLAKE3 native/sccache, SHA-256 Bazel) but every keyspace single-functions under a per-tenant R2 prefix. A second full gRPC REAPI implementation (corelink-reapi: BatchUpdateBlobs / Capabilities / ByteStream) exists but is NOT mounted in the container (near-ready). The cross-tenant network-effect moat is real for PUBLIC content (brew/pip wheels) but partial for npm tarballs (per-tenant for now).

Content-Addressed Core & Network-Effect Moat 23

BLAKE3 dedup, integrity, and the cross-tenant commons that gets faster + cheaper as more teams join.

Mined the content-addressed core and network-effect commons. The integrity spine is genuinely SOTA and shipped: a BLAKE3-256 Digest newtype that's forge-proof by construction, a VerifiedBody envelope whose only constructor recomputes+constant-time-verifies the hash, and a BlobStoreWrite trait that makes writing an unverified blob a compile error (verify-before-commit enforced by the type system, not code review). On top of that: BLAKE3 Merkle Action Cache with RFC-6962 domain separation + per-tenant HKDF-SHA256 signatures (the real anti-cache-poisoning moat), content-defined chunking (FastCDC), and one BLAKE3 hash family across native CAS / REAPI / Turbo / sccache enabling cross-protocol dedup. Dedup, LRU, edge and AC-verifier planes are built as pure-logic trait+fake skeletons with 10k-iter property tests (status near-ready: algorithm proven, live Cloudflare D1/DO conformance wiring lands at the S-0x PRR ship gates). KEY GAP for this domain's headline thesis: the cross-tenant public-deterministic commons — the actual network-effect moat — is currently WHITE-PAPER. The strategy is documented in marketing/expansion/ci-build-acceleration.md and there's a reserved cross_tenant_enabled config flag (default OFF, rejecting with CrossTenantBlocked), but no live public-deps sharing logic exists yet; today's dedup is strictly intra-tenant with deliberate cross-tenant existence-oracle masking. So the security boundary that makes the moat safe ('share public, isolate private') is built; the sharing itself is not.

Security Hardening & Operational Safety 28

CoreLink's security-hardening surface is unusually deep for an SMB-self-serve product: a two-stage PAT verifier (HMAC fast-fail then OWASP-2024 Argon2id) with explicit constant-time cold-path padding and downgrade-rejection; a Worker that is the SOLE authority for every trust header (delete-then-set of tenant-id, client-IP, scope, storage-quota, region) so nothing forgeable from the client survives a forward; verify-before-commit digest checks on the OCI plane that stop cache poisoning; per-tenant + global DoS fairness ceilings on the shared OCI upload DO; deliberate fail-CLOSED ($-ceiling/backend-fault) vs fail-OPEN (request-count SLO) postures chosen per-axis; and a full CI scanner battery (gitleaks, trivy, cargo-deny, cargo-audit, semgrep+custom rules, CodeQL, action-SHA-pin audit, secrets-matrix drift). Almost everything is shipped code; a few items (dual-approval, brew SSRF) are pure-logic crates pending production CF wiring. Problem-solved theme throughout: a multi-tenant content-addressed cache lives or dies on trust — one forged tenant header, one poisoned blob, one timing oracle, or one noisy-neighbour DoS breaks the whole product, so the hardening is the moat.
