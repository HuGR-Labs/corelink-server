### Fixed

- **fix(observability): the `oother` residue could only be enumerated by arming a credential oracle — split the gate (B-109).** The 2026-08-30 production profile measured `oother` at 139 ms on a warm authenticated PUT against 1 ms on the GET: real container work, unnamed, because the residue is computed by subtraction from the container's own whole-request clock and four phases were being subtracted into it. The only way to see inside it was `CORELINK_ORIGIN_TIMING_DETAIL=on` — which also publishes `opermit`, whose PRESENCE reports whether the Argon2id flight ran and therefore whether that exact credential was recently verified by the serving process. The dummy burn on the row-not-found arm exists precisely so a missing/expired/revoked `token_id` is timing-indistinguishable from a valid one; a header that partitions that window by name erodes the padding it is there to provide. Enumerating the residue in production therefore required opening a token-existence oracle for the length of the diagnostic window. **A performance diagnostic must not widen a security window.** The gate is now split along the line the code's own doc already drew: `ortier` (D1 tier-label resolution) and `oaudit` (the blocking durable-audit D1 write) carry no credential signal and publish **unconditionally**; `oargon` and `opermit` stay behind the flag, unchanged. The `detail_phases_enabled` doc had noted that `ortier`/`oaudit` were grouped in only as "a single, conservative opt-in ... there is currently no reason to ship `oaudit` alone" — B-109 is that reason, and it is recorded in the doc rather than silently reversed. `ORIGIN_CONTAINER_PHASES` in `worker/src/index.ts` already allowlists all eight names, so no Worker change is needed and no phase can land in `ohop` as a result of this split. **A dominated assertion fell out of the change and is fixed in the same commit:** `r2_s3.rs`'s concurrent-`list()` seam test asserted `!detail_phases_enabled_for_test() || !parsed.contains_key("oaudit")` — with the flag off, which is the production default, the left disjunct is true and the whole assertion short-circuits, so it would have passed even if that seam began double-counting its audit write under `oaudit`. It is now unconditional, which is what the double-counting property always required, and the mirror helper is deleted. Secrets-checklist row 196 is narrowed to match; `secrets-checklist-verify` OK, `validate_secrets_matrix` `code_only=0`. The residue still closes: a new test asserts phases + `oother` sum to the container total on **both** sides of the gate.
